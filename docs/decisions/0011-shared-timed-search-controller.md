# Shared timed-search controller and complete mandatory transport

Status: adopted as a validated semantic checkpoint,2026-10-18. Backend and
performance qualification remain open. Source promotion exactly matches the
112-file corrected117 closure; it implies no canonical-path rebuild.

Production and supplied root-sequence observations need the same ordering of
candidate attempts, restricted retries, best changes, publication and stop
checks. Keeping a separate diagnostic controller would let those policies drift.
One statically dispatched driver now owns that transaction. Its effects provider
supplies actual recursive work or controlled replies; the existing RootIteration
owns ranking, stable order, windows and original move identities.

The production provider creates one child before the retry loop and retains it
through both attempts. Each recursive attempt scopes and restores history before
classifying its result. Only a completed return can update the best PV, adjust
time, capture output and complete a root step. Root stopping bypasses later
roots and iteration effects. Full exhaustion alone admits the easy/iteration
check and signed terminal policy. No additional maintained root-ranking vector,
dynamic effects object, or persistent Search/Node/Position field is introduced.

CaptureSlot owns the latest completed result and its eligible published snapshot.
The shared finish policy uses actual publication facts while preserving distinct
live and offline observation. Captured work and elapsed metadata are never
restamped with terminal totals. The shared unit-charge helper preserves limit
checking, one actual N credit and then the4096-unit poll. Existing evaluator
owners retain actual R charges. The small terminal-prefix and wrapping seed
helpers extract existing formulas without moving their clock/acquisition sites.

The production recursive default retains full internal iterative ordering.
The diagnostic false capability reports the first actual disallowed entry before
phase work; it is a separate instantiation, not a production depth restriction.
Persistent diagnostic sessions use the actual Session, native command parser,
late seed hook and publication records. Their JSON admission/projection remains
in the cold adapter. No fixture answer database is linked into the engine.

separate codegen review. The exact selected source still needs its own PGO
