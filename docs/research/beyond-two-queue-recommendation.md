# Next discriminator: hierarchical child-segment recovery

2026-10-25. Source and bounded count-only evidence; no new executor selected by
this document. The [census](../../experiments/multicore-feasibility/beyond-two-census/report.md)
preserves the successful configured FULL split, canonical source66/PGO8f and main.

**Recommend a bounded serial simulation of hierarchical descendant reuse before
a parallel scheduler. Park Q window certificates as a source hypothesis.**
Direct-Q work covers28–47% of total observed N in an especially clean full-window
cohort, but96–99% of those tasks have fewer than eight nodes. At>=128 N there are
no eligible direct-Q four-way boundaries, whereas ordinary-only groups have
hundreds to thousands. Recursive Q and fixed-window mate groups do not supply
larger grain here. Counts cannot prove a tiny-task executor unprofitable, and
beta certificates remain structurally plausible; they do not presently justify
their guard/transport complexity as the next implementation. Imp2-lead's census
disposition likewise parks that direction.

The [old conflicts](beyond-two-transaction-conflicts.md) locate a concrete recovery
boundary.22 ahead tasks failed native ordered-inventory validation at event3;
that validator already reruns the real sort.34/36 ahead branches have different
canonical node work, so cheaper flat validation cannot rescue whole-branch reuse.
The sole natural first pawn rejection is35/q2/index5 at event6. There is no natural
first TT rejection; the event30 TT rollback control changes unused bound metadata
and is machinery evidence, not a measured TT conflict population. Preserve0/36
ahead accepted and every cap failure.

The next mechanism should keep the coordinator executing authoritative native
parent logic. When ordering or another dependency changes, rerun that operation;
at each actual child-call demand, look for a previously recorded descendant with
matching complete entry inputs. Try native semantic replay on staging. Accept
only a whole certified segment; on failure discard its staged writes, execute
that child natively, and retain unrelated recorded descendants for later actual
demand. A rejected parent need not discard every potentially useful descendant.
Use exact windows initially rather than adding interval proofs to ordinary search.

Each segment needs its own entry/call boundary and certificate range; the old
flat journal alone is insufficient. Match exact Node/retained arrival, chronology,
request, root/configuration epoch and relevant supplied scratch, not merely a
position hash. Continue native ordering, TT and pawn semantics, PV, killer/history
effects and N/R. A semantically accepted segment that differs from an independently
executed canonical result or state is a fatal soundness failure, never a normal
rejection. Previously committed segments remain canonical when a later attempt
rejects. Count committed maximal segments once, without adding their descendant
work again.

Avoid copying the full TT for every attempted descendant. A plausible staging
option is a reusable sparse overlay: on first touch initialize that exact native
group from the stable current canonical table, run native mutating probe/store
semantics there, then commit only touched groups after success. Rejection drops
the overlay, including late staged writes. Nested attempts must see their proper
staged predecessor effects rather than an older canonical base. This is an
implementation option requiring its own proof/controls, not permission to weaken
native metadata, displacement, recent-mark or mate-mutation rules. Instrument
touches/bytes and staging cost; the representation is not a fundamental lower bound.

The smallest informative pilot reuses the uncapped08/q2 witnesses: index2 f3f4
(151 speculative versus88 canonical nodes) and index4 c2d1 (85 versus85, but a
different native order). Record descendant boundaries anew under a bounded source
prototype; existing raw data do not contain the entries needed for recovery.
Independently execute the canonical parent and try descendants only where that
parent actually demands them. Report surviving disjoint N/R, native work still
executed, conflict depth and reasons, entry matching, log bytes, touched TT groups,
and coordinator snapshot/validation/commit/recovery costs. Separate the audit-only
canonical comparison from costs a real executor would pay; also report speculative
recording/discarded CPU and memory. Do not infer profitability from acceptance alone.

Keep the initial NoHost/timing-absent and zero-randomness limits explicit, bounded
logs and original native fallback. No relabeling an overflow as a dependency or
raising caps to hide the prior result. Include acceptance after irrelevant state
changes, late rejection after writes with unchanged canonical state, and fatal
oracle-mismatch controls. Live polls require intermediate path/control fidelity;
matching final N/R is insufficient. Branch workers must not create nested FULL
helpers when a real scheduler is later considered.

Likely scalable supply is the larger ordinary sibling population, with recovery
salvaging valid coarse descendants despite changed earlier ordering. Its useful
matching depth, queue width and economics are still unknown. A failed pilot may
show only one-node TT returns survive, windows diverge before meaningful work,
or recovery costs exceed saved work. That would reject this observed mechanism,
not queued branch parallelism generally. No prototype, build, run, cap retune,
qualification or2/4/8-thread campaign is authorized by this recommendation.
