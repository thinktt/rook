## Two concrete alternatives, contingent on attribution

**Canonical bulk priority calculation.** At the ORIGINAL ordering point, the
complete native inventory, actual map/root context and current learning snapshot
are settled. Every priority is actually demanded by `tactical::order_by`, unlike
forecast child FULLs. Compute exact per-move priorities as a compact batch, using
shared parent projections or disjoint arithmetic workers; keep the original
priority<=1 partition/reversal and gap6/1 permutation on the coordinator. Source:
`ordinary.rs` actual order call, `ordinary_policy.rs:534`, `tactical.rs:338`.
No search may mutate learning while workers read it; do not snapshot the whole
Learning/TT per task. Join before permutation/child entry. Later IIO ordering is
another CURRENT-state demand, not reuse of stale priorities. Q has different
priority inputs and needs explicit separate admission.

This escapes branch-transaction conflicts and unused-child work: it computes
only keys the canonical sort already requests, without a cross-position index.
It does not escape tiny inventories, dispatch/read/result costs or cheap bounded
priority arithmetic. Whole ordering time also includes the prescribed permutation;
that cost is NOT offloadable merely because scoring is independent. Existing
history/order experiments do not establish a profitable parallel scoring grain.
A small same-parent score-array experiment is meaningful only if current scoring,
not simply the enclosing sort, has substantial exposed cost.

**Reversible search-position executor.** Replace copy-child Position production
with one mutable placement plus per-ply undo records at actual ordinary/Q/null
entry; retain ordered TT/learning and per-ply evaluation state. Supply is certain
entered edges, not speculative branches. Undo restores chronology insertion
indices, all rule/identity/plane/starting-unit fields and retained inheritance on
normal, stop and error exits; it must not roll back prescribed learned/cache
updates. Original predecessor inputs remain authoritative throughout recursion.

King requires identical parent/child observations, not a160B physical Position
copy. But predecessor/value snapshots can require much of that data anyway;
removing a source assignment does not prove a compiled copy was removed. A compact
predecessor projection must be proved for each real consumer, including IIO/null,
rather than assuming parent placement is dead. This differs from the old isolated
40B-undo microexperiment and parent-borrow/compact-recursion retunes, none of which
established an integrated restoration win. See [position receipt](position-layout.md).
Only a large actual transition/copy pool could justify this higher-risk rewrite;
current evidence has not found that pool. No prototype is recommended now.
