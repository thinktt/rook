# Consumed ordinary-order prefixes after the recovery pilot

2026-10-25. Source/existing-result assessment only. No new source variant or run
selected here; current recovery source, policy and evidence remain frozen.

**A consumed-prefix certificate is a credible next discriminator at ordinary
depth1/2. The current reports cannot quantify how much coarse work it recovers.**
Ordinary-order mismatch caused63/81 semantic rejections in08 and5,073/6,213 in35.
Those are attempted certificates, often nested, not additive lost work.35 ahead
reuse recovered22,573 nodes but only in13,509 segments, largest118;08's largest
was6. The old35/d7d6 whole-branch order rejection covered36,985 speculative versus
43,402 canonical nodes. Changing only that root order check cannot certify the
whole branch when actual node counts differ. A useful prefix change must instead
coarsen otherwise identical descendant paths, not merely admit the same best move.

The promising source boundary is exactly ordinary requested depth1/2. The
quiet-mate loop requires remaining depth at least3; initial and tail IIO require
larger depth. Keep full-order checks elsewhere and for Q. A null trial can still
precede the ordinary main loop and must retain all original replay and accounting.

At this boundary the main consumer uses an ordered contiguous prefix through
the last examined candidate. It can skip recursion using a frontier estimate
while still examining that candidate; **skipped moves belong to the prefix**.
Only a native loop break leaves a genuinely unvisited suffix. The failed first
fixture showed fewer recursive children after changing order, not evidence of an
unconsumed suffix: frontier-skipped candidates still consume positions in order.

Replay must rerun the complete native `order_by` operation, including priority
handling and gap6/1 sorting, on the unchanged inventory. Preserve its length and
input multiset; compare every move in the consumed prefix. This allows the freshly
computed suffix to differ, without using speculative suffix bytes or replacing
the sort with same-best-move validation. The main loop does not consume priority
numbers after sorting. Its extension setup reads the complete inventory for
count/set properties, including unique recapture; those properties are permutation
invariant. At depth1/2 there are no IIO permutations/accumulated suffix flags to
add another consumer. Exact entry windows, retained state, predecessor, supplied
inputs and all native effects remain unchanged requirements.

Current in-memory records contain enough consumer evidence for a conservative
derivation. Each complete ordinary segment stores inclusive `Stats`, direct child
relationships, a journal range and its depth. Subtract the inclusive examined
counts of **all immediate charged children**, including null/scout/retry/Q, from
the parent's examined count. The remainder is its own main-loop prefix length,
including frontier skips. Require complete coverage: parent N minus those child N
must equal1, all needed child outputs must exist, and the owner must have exactly
one local-ply `OrderMain` event. Require1<=prefix<=inventory length. On any missing
or capped evidence retain the full-order predicate. Do not infer the prefix from
the number of child segments or the first successful child.

The raw pilot serializes aggregate rejection counts, accepted ranges and source
identities, rather than the complete forests/consumer annotations. Consequently
we cannot retrospectively state what fraction of the5,073 rejections affected
only unvisited suffixes or how large their unchanged subtrees were. Window
differences also caused20,688 candidate-key comparisons in35; these are not
independent calls, and prefix validation does not address them.

Recommend one same-policy discriminator, after closing the present record:
annotate eligible events with the proven consumed prefix, keep full-order control
and all other checks, and compare both against native canonical execution on the
same bounded08/35 witnesses. Count newly surviving coarse maximal segments and
their costs, not acceptance alone. A stable first hint plus a native child TT
cutoff can provide a plumbing control with a changed unvisited suffix; label its
one-node child as a correctness witness, not useful grain. Also require failure
when a consumed move changes, include a frontier-skipped move, retain full checks
at higher depth/Q, and keep cap fallbacks and fatal oracle mismatches.

This has a clearer work-elimination mechanism than tuning the existing tiny
segment matcher immediately. Current35 ahead lookup/staging/replay/commit cost
59.095ms versus21.383ms of instrumented removed-call proxy. Coarsening can remove
thousands of coordinator child-entry matches while reusing more valid computation.
Repeated epoch/history copies remain prototype costs, and even a successful
prefix pilot would still require an actual bounded2/4/8-worker comparison, with
speculative CPU, snapshots and memory charged. It is not a performance forecast.

The finite oracle's shared-state comparison remains root-final only. Preserve
the disclosed transient-overwrite limit; stronger local-effects auditing is
required before adoption or removing the oracle.
