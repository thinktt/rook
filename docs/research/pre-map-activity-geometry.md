## Independent work and bounded representation

Activity329–405 chooses rays/knight targets, friendly skips, transparency,
direct/additional transition and rook vertical multiplication from Position,
kind and direction alone. Orientation/rook-seventh selection60–74 also needs
only Position. Prepare destination geometry, not categories or pressure marks.

Choose a fixed **128-byte private buffer per color**: fifteen eight-byte source
records plus one friendly-square mask. Each slider direction packs two prefix
lengths0..7: d ends through the first occupied target, or ray end if empty;
v ends through the first opaque target, or ray end. For index j<v, skip friendly
squares and classify direct exactly when j<d. Multiple transparent occupants
change v but never reverse additional state. Knights use one byte as admission
bits over their existing ordered KNIGHT_SOURCES entries. Source/kind identity is
implicit in the same immutable Position's original N/B/R/Q list order; no header,
hash, Vec or cross-job geometry cache is needed.

Position has16 list slots/color and exactly one king, hence at most15 Activity
sources, even joined15Q/N/B/R setups. Rays have at most seven targets. The
friendly mask can derive from the existing coherent tag planes (`attack_planes`),
not a rebuilt board view; public stale planes never authorize this route.
The128B bound excludes existing marks/numerical locals, compiled padding/spills
and new shared staging storage. Initialization, endpoint writes and consumption
are real costs; no compiled-frame claim follows from this bound.

The second pass replays the original ray prefixes/order. It avoids recomputing
transparency/termination but still decodes endpoints, filters friendly squares,
loads mailbox victims and visits numerical destinations. Alternatives cost more
storage: direct/additional masks240B/color; byte tokens up to405 targets plus
piece boundaries. They are not the recommended first implementation.

Extract ONE shared per-target numerical consumer for native traversal and staged
replay. Keep direct_category/capture priority, marking, piece_score_kind407–447,
king pressure and Shelter as their original numerical owners. Direct category
sums and marks wait for the final capture-adjusted category, including category0
weak marks. Additional targets add total and one semantic R, not direct category
sum/marks. Preserve source profile penalties, normalized pawn-based knight
exemption, low-mobility thresholds/conditional relation query, per-piece curves,
color rounding and coordinator weighting. Produce/charge R at original FULL
consumption; geometry alone publishes no evaluation/work event.

## Staged storage, retirement and abandonment

One immutable tagged initial input distinguishes Supplied(actual map) from
FreshPosition. A separate initialized Influence cell and mapReady epoch carry
the owner-produced map. Do not mutate a whole Packet while helpers borrow it.
Supplied jobs use their exact map and do not wait for/read the staged map cell;
tag/storage/layout changes still count in matching controls.

1. Owner requires Flight::None, initializes input/metadata and releases request(g).
   Helpers acquire it and prepare private geometry. They do not write shared
   marks, rows, caches or search state.
2. Owner executes original ensure: build/install canonical caller scratch and
   charge its single influence_builds/coherent-build event. Copy the complete
   128B map to the separate cell; release mapReady=g. Helpers acquire exact g,
   then directly borrow that immutable map and finish original side arithmetic/
   Shelter. No helper-local complete-map copy, peer barrier or owner phase wait
   is required; cache transfer/readiness polling remain costs.
3. All initial/map borrows end before original scalar output/done publication.
   Both actual done and ended output reads precede slot reuse; next request
   carries the reverse output edge. Parent scratch remains independent across
   descendant jobs. Supplied gaps never satisfy a later fresh equality by a
   stale mapReady. Preserve the original completion SC-RMW/Sleep protocol.

Existing sampled publication/ready intervals start earlier and include new
geometry/map waiting; label that boundary rather than treating shorter residual
join as saved work. Aborted staged requests may add physical readiness/discard
events, while original FULL/influence/R charges retain their demand owners.

**Current cleanup alone is insufficient before mapReady.** Last-scope close
sets active_scopes=0 and waits for real parking; a helper polling only mapReady/
stop would deadlock. Add a last-scope cancellation path to that wait: when it
observes inactive, return an owned Abandoned outcome ending EVERY initial/map
borrow. Only afterward record seen=g and enter existing Control-serialized park.
Advancing seen is essential because park rejects an unseen request. Both actual
PARKED/exited acknowledgments let owner Discarding retire; no mapReady, done or
successful evaluation is fabricated. Request Acquire orders activation's earlier
active_scopes=1 store, excluding a stale pre-activation zero. Reopening cannot
publish another request before both real idle acknowledgments.

This is strictly a depth-zero contract. restore_activation(saved_depth>0) leaves
the outer owner active and is NOT retirement. On the proposed fixed caller graph,
the pre-map segment has no Host/observer/poll or recoverable Result return: native
map construction returns Influence. After request publication it must either
publish/join or unwind. Selected-path owner catch_unwind sites are Search
activation wrappers(engine234–253) and standalone Evaluator609–621;
finish_activation325–349 resumes the original panic after nested cleanup. Thus
unwind reaches the outer saved-zero owner before external receiver reuse or a
next dispatch. A standalone private combined entry must enclose its complete
staged prefix at saved zero. An internal catch/retry or normal/error return with
FreshAwaitingMap would invalidate this proof and require an additional cancel
seam; neither is proposed. Helper failure still sets stop, ends peer waiting and
actually joins both. Existing healthy callback/inventory unwind reuse is preserved,
not silently converted to permanent terminal failure. Native abort remains distinct.

## Economics, history and smallest next discriminator

For illustration only, let M be canonical map build; P the existing packet
publication; P0 initial publication; Pm owner map copy/publication; C owner local
work; Li pickup; Gi geometry; Ni remaining side/Shelter work; Ki map acquisition;
Di replay/materialization overhead. Include private buffering in staged G'i.

`baseline = M + P + max(C + I_b, max_i(Li + Gi + Ni)) + J_b`

`staged = P0 + max(M + Pm + C + I_s, max_i(max(Li + G'i, M + Pm) + Ki + Ni + Di)) + J_s`

These are dependency sketches, not measured decompositions or speed bounds.
P0 precedes M; map delivery, the second pass and storage are not free. More
importantly, I_b/I_s are readiness-conditional ordinary/Q inventory hooks, not
fixed additive savings. Earlier helper completion can suppress eager generation
and move demanded work after FULL. The later search tail changes too. Preserve
both winning hooks and price whole search; min(map,geometry) is not a saving bound.

Three lanes independently building complete maps do not solve this: each helper
still pays M before Activity, and owner pays M before C. With equal map costs,
the common M remains on the critical path while CPU duplicates it twice. Removing
the old peer barrier alone supplies no latency argument for replication.
