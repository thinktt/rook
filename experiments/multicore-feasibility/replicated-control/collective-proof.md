# Three-lane scalar collective

`CollectiveControl::new()` initializes two complete scalar slots for each of exactly three unique, nonclonable writer lanes: owner0, white1 and black2. Contributions and gathered results contain owned Copy values only. Owner Activity/Shelter/tempo fields must remain zero; wrong-role contributions fail before publication. Control clones expose cancellation and cold necessary epochs, with no slot-writing capability. The library boundary requires `panic=unwind`; the parent runner owns catch/cancel/join for every actual started thread.

For epoch g, a lane writes its parity slot and publishes ready=g with Release only after its previous gather has ended every read of g-1. Completing gather g-1 acquired every publisher's release g-1, each following that publisher's last read of g-2. This retires all readers of the parity slot before its overwrite at g. The first two epochs use initialized cells without prior readers. Epoch increments are checked and cannot wrap.

A reader acquires every ready>=g before copying each exact slot generation g. Equality would reject a valid peer already at g+1. Such a peer cannot overwrite g's parity at g+2: it must first finish gather g+1, including acquiring this reader's publication g+1, which follows all this reader's accesses to g. Slot reads therefore remain protected until their owned Copy results exist. Per-slot generation and role checks reject inconsistency; no reference escapes a read. Neither cancellation nor terminal publication modifies slots or ready values. The argument survives a cancelled partial gather because that lane can never publish another successful epoch.

All three actual lanes spin on ready/cancellation; production has no completion Condvar, single-waiter latch, hot mutex, clock, timeout success or observational counter. The reason mutex is cold failure detail. `finish` releases a separate terminal flag after the last local reads. A peer already published beyond the finishing epoch is divergence. A waiter seeing terminal with ready<g reloads ready after the terminal Acquire before cancelling; terminal at g permits remaining g readers. Unfinished Drop cancels and publishes terminal without fabricating ready. Arcs keep storage alive through cancellation/unwind; actual thread joins remain the runner's obligation. Cold `final_epochs()` reports actual publications, including partial failed gathers.

One prospective layout is fixed before data: each role has a `repr(align(64))` Publication containing its ready/finished atomics, a separate aligned two-slot storage object, and a separately aligned cancellation word. Distinct writers therefore own distinct publication/storage regions. This is neither a cache diagnosis nor a padding sweep. The added storage, address/poll traffic and scalar copying remain charged; no speed claim follows. Cold native `storage_bytes()` reports `size_of::<Shared>()`; test-only gates change test-build storage and are absent from native reports. Protocol and the eight controls remain unchanged.

Selector `replica_collective::protocol_tests` contains eight controls: typed repeated gathers/owned-result reuse; a delayed reader with fast peers one epoch ahead; cancellation while waiting; lower/ahead terminal divergence; same-epoch terminal peers; unfinished Drop; wrong roles/owner fields; and actual MAX publication followed by overflow cancellation. MAX setup changes only private local counters while all lanes are quiescent; no ready value is forged. Source-only implementation/review was performed, with no builds, tests, native execution or Git operations.
