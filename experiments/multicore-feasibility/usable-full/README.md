# Usable two-thread FULL mode

This research integration restores the measured5612 source before applying a
small normal-mode cleanup. See [plan](plan.md) and the explicit
[source-restoration ledger](source-restoration.json). Failed implementations and
their reports remain in research history; main and the frozen a977 image/profile
remain unchanged. This directory does not establish adoption or qualification.

The ordinary binary defaults to one thread. `--threads=2` permits one persistent
Activity/Shelter helper. Positive larger requests still configure only two.
Explicit `--threads=8 --inspect-threads` prints requested8/configured2 JSON and
exits; ordinary protocol operation prints no configuration banner. Library
Evaluator/Search/Session expose matching setters and inspection.

There is no engine CPU pinning or elapsed-time failure deadline. A helper inherits
the creator's allowed CPUs, parks outside owned searches/direct calls and joins
at shutdown. Logical work and Host polling remain on the coordinator. An owner
that needs a finite deadline must supervise the process. Active searches may
still consume helper CPU while Host callbacks block.

`pipeline.py --output FRESH_EXTERNAL_DIRECTORY` runs the selected focused checks,
one generic build and fixed48-life comparison. Invoke it under housekeeping
affinity `0-5,8-13` only after announcing the native window. `collect.py` uses an
external supervisor and first-input gate to verify14/6 placement; `focused.py`
separately checks one-CPU liveness. `reconcile.py RAW_DIRECTORY` audits saved
streams, placement and accounting without launching an engine. Source checkpoints
precede execution; measured results will be recorded separately after closure.
