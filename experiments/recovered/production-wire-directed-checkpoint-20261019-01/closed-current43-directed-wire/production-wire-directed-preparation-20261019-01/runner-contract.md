# Small future interactive runner contract — not executable or authorized

Use one fresh direct Popen of the pinned ordinary image per cases.json entry, with argv `rook2-exact --work-clock=kingwcr`. No diagnostic seed command, explicit seed, post-work formatter, wrappers, additional searches or reference run. Native and controller both inherit exact housekeeping mask0–5,8–13; no CPU14/15. Natural POSIX seed acquisition remains, with released fixture rnd0. This is functional evidence, not CPU timing.

Each step writes exact ASCII bytes with a complete write loop and explicit flush, retaining every actual write chunk and monotonic timestamp. For the two go+queue packets, verify length<=actual PIPE_BUF and perform exactly one write; a partial write is retained and invalidates the planned atomic-availability witness, not silently completed into an alleged atomic write. Queue all earlier setup bytes before waiting for their ordinary replies. Parameter acknowledgment and empty `cm_parm` query are real existing commands, not a new handshake. Never queue quit/EOF during search.

Read stdout and stderr concurrently through selectors into raw files before assertions. Parse records only at LF, preserve partial suffixes and enforce ASCII/no-CR output. Match all expected bytes, interleaving and multiplicity exactly. Case3 statuses must parse all numeric fields and canonical minimum widths, with N12288 then16384; elapsed must be nondecreasing and remaining excludes current root. Path bytes are retained, not declared fully verified by this scheduling test. The original first-stop expected file uses released semantic fixture/PV formatter rules, not current engine output. No source parser or chess search is emulated.

Record the input/expected steps, every write/read chunk offset/time, exact stdin/stdout/stderr, native PID, initial argv/source/artifact/spec/helper identities, native code/signal and before/after identities. Stream equality alone does not replace actual wait/exit. After the expected last reply, explicit-quit cases keep stdin open until native exit; the EOF case closes stdin only while idle. Drain stdout/stderr through EOF, reject extra/partial output, then observe actual native exit0 with no signal. No assertion failure is repaired by omitting bytes or changing expected streams.

Prospective safety limits reuse accepted check_live.py's30s per output record,120s per lifetime,4MiB per captured stream and5s termination/cleanup; add a finite600s total for the fixed four lifetimes and64MiB total retained output/metadata envelope. Bound stdin separately at16KiB/lifetime; actual packets are below it and every record<=1023. Retain only up to each cap, record observed/discarded counts and invalidate on overflow. No retries/outlier deletion/cap tuning follow a failure. A small100ms no-output fragment interval is a fixed observation design, not a required engine speed threshold. Unsupported own-pipe FIONREAD means incomplete fragment-consumption evidence, not permission to pretend a quiet sleep proved it.

The image is the known single-process ordinary CLI: direct Popen, start_new_session=True, no detached controller/Valgrind layer. A future runner must retain its exact native PID and owned group, send TERM then KILL as needed and require actual exit/drained pipes within a single five-second monotonic cleanup budget. Unknown/delegated descendants or cleanup-unconfirmed make the result invalid and stop later cases. Process-group cleanup is not claimed for arbitrary binaries that escape/daemonize; there is no such source path in the selected normal CLI, but runtime support/ownership checks must be reviewed with the concrete runner. Do not import the recently frozen hot-cost supervisor or edit it for these interactive checks.

On any failure preserve raw bytes, observed exits/timeouts/signals, cleanup status and exact failed assertion, then stop the batch. Distinguish valid observation contradicting expected protocol behavior from a precondition/scheduling/environment/resource failure. In particular, missing four-poll reachability alone does not justify an engine defect claim. Write only an allowlisted final summary to stdout; detailed records stay in the new execution directory, whose path/absence must be frozen before any later launch.

No runner has been implemented here. Parent must separately review/authorize an implementation and launch. There is no actual outcome, no runtime closure evidence and no qualification claim in this design packet.
