# Isolated functional-cost driver: source handoff

Four route rows implement three released semantic units: eval-scalar/eval-coherent -> evaluation-opening; position -> position-history-opening; search -> search-light-start. CLI: `--mode verify|measure --row ROW --input PATH --iterations N`; verify requires N=1. Input is exactly the public request.input, without expected data.

Only three existing files change: Cargo.toml/lock acquire cached serde_json1.0.154; evaluator.rs appends the nested module declaration. Two Rust files are added. All native numerical/search bodies and195 inherited test bodies remain literal old bytes. No parser/compiler/native execution was done by this owner.

`verify` returns `{row,completed,projection,sink,work}`. `measure` returns `{row,completed,local_cpu_ns,local_wall_ns,sink,work}`; work fields are `chargedSearchUnits` and `chargedRelationQueries` as exact JSON integers. Measurements sum actual per-sequence charges. The same invoke and consumer run in verify and measure. Serialization is cold; expected data belongs only to the independent checker.

Cold work includes input decode/admission, all sequential legal descriptor resolution, root coherence validation, fixed evaluation context, physical buffers and search table provisioning. Local loops include actual reset/copy/native transitions, selected full/fast numerical owners, check state, typed complete projected observation and consumption. Evaluation clears only actual pawn/stats state per invocation, then creates a fresh root Node, retaining numerical state through that invocation's steps. It does not call begin_search or clone Evaluator per invocation. Coherent maps are only used after normalized root/actual preadmitted descendants were validated. Scalar row uses unchanged public Influence::build. Neither row caches a produced map across steps or sequences.

Search uses existing Search<false>::run_seeded_iterations with seed0/rnd0 and node budget4095. All raw callback returns are captured. The final return slice pairs the actual last Iteration.candidates visitation order; no fullTrace and no expected root scores. Existing root preparation, logical TT clear (including wrap scans), pawn/learning reset and owned recursive work stay in each loop. Physical arenas/table are provisioned once, a disclosed difference from a fresh allocation-per-invocation adapter; root preparation stays inside this owned-call scope, so do not claim reference narrow-inner-search equivalence. Actual result temporaries and callback/vector work are included. Last typed observations remain alive for cold serialization; final destruction stays in whole-lifetime accounting.

The sink covers semantic placement bytes, side/rights/EP/counter, active chronological groups, all identities/phase, evaluation kind/check/inherited+retained/reuse/R/finishing fields; search covers complete initial candidates, depth/score/PV/work and final ordered root results. Its hash is consumption evidence, not a semantic oracle. Separate before/after original full projections establish actual output. Every timed input is opaque through black_box and the final sink is emitted; there is no per-invocation timer or JSON serialization in the loop. POSIX FFI is restricted to a valid repr(C) Linux64 process-clock output; invalid/unresolved clocks fail.

Focused validation proposals for parent execution: (1) exact public projection for each of the four verify routes; (2) scalar/coherent projections match the same opening unit, including every R/cache-reuse/retained stage; (3) measure N=2 has twice actual work and deterministic same-N sinks, then calibration >=1024search to exercise generation wraps; (4) malformed schema, unknown row/mode, duplicate CLI flag, illegal move/null and zero iterations fail without reporting a completed batch; (5) optional alternate admitted inputs demonstrate parameter/move/result data dependence. These are proposals, not executed results. Root owns builds, correctness execution, PGO and all timing.
