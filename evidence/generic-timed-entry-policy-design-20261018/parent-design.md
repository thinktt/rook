# Immediate generic-timed IIO entry fence

Parent design, source inspection only; no execution or implementation authorized by this memo.

The released generic-timed-search contract requires failure at actual internal-iterative-ordering entry. Current final Stats checking does not establish that boundary. Broader ordinary/joined production still permits full IIO. Keep the native capability specific to the diagnostic invocation and preserve production defaults.

Preferred boundary: preserve public/default visit_ordinary as a true specialization wrapper over one visit_ordinary_impl<const ALLOW_IIO: bool>. Propagate ALLOW_IIO through every actual ordinary recursive/null/scout/retry call and ordering_phase specialization. Extend the existing timed implementation through the same const specialization, preserving run_work_timed as true and exposing a separately named bounded diagnostic entry that selects false. Do not add policy state to Search/Node/Position or another identity/observer type to every recursion. The false branch in ordering_phase increments the existing actual entry counter then immediately returns a dedicated Stopped variant before candidate visits, shallow passes, extension queries or ordinary child execution. Successful response still validates terminal zero entries; failed invocation cannot project a partial Outcome. History unwinding, timing cleanup and existing per-search errors must propagate exactly.

Alternatives considered: a new runtime Search bool (unnecessary hot state/branch), a new Search generic capability (wider type and map_host surface), Host associated policy (smaller code surface but conflates external I/O host with ordinary-search capability), or final counter rejection (does not meet explicit placement). The method-local const has a bounded code duplication cost only in the adapter, which instantiates both capabilities; normal native instantiates only true. Renaming/outlining can still change generated production code, so codegen/layout and matched whole-search evidence remain required.

Before implementation, inspect exact post109/108 native source and enumerate all internal call sites to prevent a default-true escape. A meaningful native test must force actual initial and tail ordering entry in the false specialization, verify entry count1 and passes/children0 with history restored, and compare default enabled execution to inherited IIO witnesses. The exact generic personality parser must admit the full thirty-field numeric domain, root/history domain and explicit zero seed, without reusing narrower seededTimed fixed-vector admission. Reuse only the actual timed projection/rendering owners, never duplicate their formulas. Generic successful bounds are six entered iterations,8192 charged units, at most256 unchecked roots and PV63, history255; component limits do not narrow ordinary protocol ingress.

No performance or source adoption claim. Parent must review the actual patch and codegen; preserve source failures through a fresh revision. This is a regular diagnostic capability decision, not a new architecture or advisor approval dependency.
