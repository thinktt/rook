# Node child-copy triage: NO-GO on current evidence

Do not select a source trial from this evidence. The simple proposed shape—copy a complete local Node, mutate its Position, then return it—is exactly rejected experiment28/decision0018. A genuinely caller-owned destination with a unit-return transition would expose a different ownership boundary, but current43 has no established extra160-byte transport in the inspected saved captures. Source value syntax alone is insufficient to justify it.

**Prior work first.** Decision0018 and its preserved source patch are unambiguous: experiment28 changed only Node::child from `Position::played_unchecked` inside the returned Node to a copied local whole Node followed by apply_unchecked. Its actual generic25 control2940 still copied160 bytes into a temporary and another160 into the Node return place. Triald8a7 kept the first160 and enlarged the second to176; local reservation grew168→184. No native test/timing followed; it was rejected at its mechanism gate. historical28-copy-windows.txt extracts the small saved call windows, including explicit0xa0/0xb0 byte counts and same apply target. This is historical generic evidence, not current43 lowering or a CPU result. Earlier position-design/layout research also leaves make/unmake unselected; that would require different restoration ownership and is not an extra-copy fix.

**Current source.** Node::child (evaluator.rs:48–91) is byte-exact to the old28 control method. Current played_unchecked/apply owner region is also exact to the saved25 source. Node computes moving/victim/promotion/castling nonking-square balance first, then obtains an owned child Position; it propagates positional/progress, updates nonking balance and wraps age once. Position::played_unchecked (251–255) copies the parent, calls apply_unchecked on that child and returns it. apply_unchecked (275–352) updates real victim/mover chronology, placement hashes/planes, castling rook, rights, retained EP, halfmove and side through the existing owners. The parent remains immutable. A distinct owned child state is necessary under this copy-child design; eliminating it would be a make/unmake redesign. Returning that abstract value does not by itself prove another physical copy.

The existing callers already keep local child ownership while lending it into recursion: ordinary mate probe912, main child1006 and tail/IIO child1151; null is a separate operation. Main1006 records inherited Retained, pushes history, searches, then scout-retries the **same refreshed child**, and pops history before propagating Result (1007–1067). Q408 may construct a prepared child for repetition/reply tests before the final own-king screen, and Q443 reuses it or lazily constructs once. History surrounds those probes and the eventual recursion. Timed root613 constructs ActualChild whose node persists across retry; first_iteration65 has its own owned child. None of these source locals alone identifies a removable ABI transfer, and a160-byte caller Position snapshot must not be mistaken for child-return transport without operand/lifetime evidence.

**What would actually differ from28.** A private operation that mutates the actual caller's fresh, distinct child storage and returns unit can avoid a *value-return boundary* in source. Public Node::child could remain pure, backed by the same numerical transition owner. Merely creating a local Node inside that public value-returning method is28 again. A true caller-slot form changes hot callers and alias/lifetime contracts, may copy all176 historical Node bytes initially, and may still produce spills/moves. Safe initialized ownership is needed; no unsafe uninitialized slot, new per-ply state, or parent mutation is justified here. No prototype is provided or selected.

The current nonking-square arithmetic and its pre-transition reads/panic order must remain before apply; the age wrap/Retained struct formation currently follow the returned Position in field-evaluation order. A private fresh child may be unobservable until complete; an externally supplied existing destination could expose partial mutation on panic, unlike the pure public return. Public API signatures/parent ownership therefore cannot silently change. Native apply must remain the one placement algorithm, with exact chronology/EP/victim rules. History publication, charges, prepared-Q construction timing, retained refresh across scout/root retries and child reuse cannot be moved/reset to make the source look simpler. These are semantic obligations even though the measured release profile aborts on panic; public/test builds still have their own behavior.

**Saved evidence and missing discriminator.** The inspected43 generic/PGO complete captures are Influence::build_coherent at1ff00/15c30, not Node/Position construction. Their headers are retained in source-proof.json; they do not answer this ABI question. No ELF, new disassembly, layout probe or current profiler data was read. Historical160/176 sizes and transfer counts are not automatically promoted to current43 machine facts, despite identical owner source.

A future bounded discriminator, only if parent separately selects it after this window, would need: actual current43 normal ordinary/Q/root call sites and inlining roles; resolved producer destination/source operands proving the necessary initialization and a distinct post-apply transfer; then evidence that an actual caller-slot/unit-return boundary removes the latter without relocating it or increasing frames/spills elsewhere. Q prepared-child and retry routes need separate identification. The earlier generic gate shows why a source-level temporary rewrite is inadequate. No current attributable copy cost, dynamic count or speed saving is established; a full Node/Position entry-copy census or make/unmake revival is outside this triage. Recommendation remains NO-GO, preserving28's rejection.

All inspection was frozen own source/research, small source hashes and small saved textual assembly onH. No live/proc scan, runtime, build/test/compiler/binutils/profiler/archive/Git or engine source edit occurred.
