## 1. Quantity preserved, including physical overflow

Released `evaluation-relations.md:15–24` normalizes physical weak/queen/rook/minor/pawn counts with radices2,2,4,4,4, discarding the final quotient. The normalized byte is therefore

`(weak + 2*queen + 4*rook + 16*minor + 64*pawn) mod256`.

This follows by successive quotient/remainder decomposition, including carries between **categories**, rather than separate category saturation. `77–80` expressly permits commutative source summation. Scalar `influence.rs:17–23,164–167` uses exactly these weights and wrapping_add. The desired proof is full-byte equality, stronger than equality of a relation label or capped multiplicity. It includes the released eight-minors+two-pawns=256→0 example (`131–134`) and every coexistence/overflow pattern. Adjusted exclusions remain a later saturating subtraction from that normalized byte (`influence.rs:242–243`; contract119–129), never physical subtraction before normalization.

For a target t, define its current counter `V_t = sum_b (((planes[b]>>t)&1)*2^b)`. In `coherent.rs:136–143::add<s>`, bitwise XOR computes the sum bit, AND computes outgoing carry, independently at each t. Bits below s stay fixed; the ripple starts with mask_t at s. At bit7 the code keeps XOR and discards outgoing carry, exactly modulo256. Thus the invariant after each call is `V'_t=(V_t + 2^s*mask_t) mod256`. No wordwise numeric addition leaks a carry to another square. This argument covers every initial256-byte value and any finite number of additions; it needs no small physical-count bound.

`add_slider<s>` (`146–160`) combines normal weight2^s and weak weight1. With W=0 it uses the same adder. Otherwise the lower0..s−1 ripple starts at W; every subsequent carry is a subset of W. Because N∩W=∅, its carry at s cannot overlap N, so `carry|normal` equals their arithmetic sum of bits. The shared upper ripple is therefore exactly addition of `2^s*N_t+W_t`. This disjointness is a substantive precondition, not established merely by the debug assertion; geometry below supplies it. Production instantiations are P6/N4/K0, B4/R2/Q1 (`48–70`), exactly weights64/16/1/16/4/2. All shifts and array indices are fixed/in bounds. Overflow is intentional modulo256, not a checked integer addition that can panic in a crowded position.

Different physical sources are still separate loop iterations and separate calls. OR is used only to gather one source's destinations, never to merge contributions from different pieces. Repeated promoted queens, multiple knights and coincident rays therefore retain multiplicity; source-list reorderings commute mathematically. ## 2. Exact transpose, not a square permutation

The twelve `swap` calls at `coherent.rs:163–183` are three stages k=2,1,0, with s=2^k and masks selecting columns whose within-byte bit k is0. For each row pair i,j=i|s with row bit k initially0/1, the XOR/shift/mask exchange swaps precisely `(row=i,column bit k=1)` with `(row=j,column bit k=0)`; equal row/column bits stay fixed. Hence each stage exchanges one row-index bit and one low column-index bit. Writing target t=8h+l, after all three stages input plane-bit b at target8h+l has moved to output word l, bit8h+b. Thus output word l's byte h is **the complete original target byte8h+l**, for arbitrary512 input bits. The masked shifts do not cross an8-bit tile boundary or lose a selected high bit. This is a bit-permutation proof, not reliance on random matrix tests.

The actual SSE2 network at189–200 then interleaves these bytes in the correct order. The epi8 pair stage groups l0/1,2/3,4/5,6/7 at each h. The low/high epi16 stages form l0..3 and l4..7 for h0..3 / h4..7. The epi32 stages join l0..7 for successive h pairs: the four stores hold targets0..15,16..31,32..47,48..63.
