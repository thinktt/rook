# Current51 pawn consumer: no material trial justified yet

**Recommendation: no new pawn implementation selected from this review.** One distinct source mechanism survives the bounded history check: retain the pawn-file occupancy masks alongside the already-retained structural descriptors, rather than rebuilding them in the piece-term consumer after every cache selection. It is semantically plausible, but its entire removable source setup is at most sixteen descriptor visits and sixteen logical zeroed bytes per admitted `raw_piece_terms` call. No current51 isolated cost or emitted-copy evidence establishes materiality. The larger pawn-progress owner does not consume these masks, so its known prominence cannot justify this proposal.

## Exact repeated work and prospective boundary

`pawn_terms::raw_piece_terms` creates `files:[[u8;8];2]` and ORs every retained descriptor into its file/rank byte (`src/pawn_terms.rs:244–257`). It does this on retained full-identity hits as well as misses. The later N/B/R loops consume those two arrays for adjacent-file ahead/behind predicates. `compute_with_phase:368–389` invokes this producer only when opening+middlegame>16; the phase-gated call population must be respected. A full evaluation selects one `PawnStructure` and passes it through current structural penalties and then current progress (`evaluator.rs:392–428`).

A future representation hypothesis would store **only these16 derived bytes** in each private retained group, built on the same miss that produces descriptors. A private selected view could expose immutable descriptors plus their file masks to one shared numerical piece-term body; the existing public `PawnStructure`, `Selection`, fresh/raw diagnostic APIs and their result formats would remain unchanged. Public raw calls would still build the local masks from their supplied descriptors. The private cache-hit path would bypass that local reconstruction, not pawn classification, current penalties, current piece/map reads, races, phase scaling, weights or finishing. This is not cached weighted evaluation and does not add Position/Node fields or Influence provenance.

This is a concrete interface possibility, **not** a source proposal or actual cost finding. Adding16 logical bytes to each of128 retained groups adds2048 logical payload bytes. Actual group stride/cache residency/Search layout, copy/return ABI, selected-view borrowing, full-owner inlining and frames are unknown. Extending the existing owned `Selection` would introduce more value transport; a borrowed private view instead complicates the `&mut Evaluator` lifetime. All consumers must finish borrowing before whole-self finishing/observer callbacks, and the reused bit must remain available without extending that borrow. A snapshot that merely relocates reconstruction/copies would fail the discriminator.

## Semantic traps the representation must preserve

Full identity equality deliberately reuses the earlier arrangement and order even for genuine pawn-set collisions; zero identities initially reuse EMPTY (`pawn_structure.rs:68–135`; released `retained-pawn-structure.md:27–54`). Therefore masks must be derived from **retained descriptors**, never the current board/AttackBits or a new stronger pawn-set key. Clear/replacement must initialize/replace them atomically with the descriptor result. Reordering equal-identity requests leaves retained descriptors and masks unchanged; different identities in the same group replace both.

Piece activity consumes that retained arrangement without current-membership filtering (`pawn_terms.rs:249–256`; `retained-pawn-subtotals.md:45–51`). Structural penalties and candidate progress intentionally use different current-membership rules (`pawn_terms.rs:338–360`; `pawn_progress.rs:253–299`; `retained-pawn-candidates.md:29–45`). The latter cannot be folded into this representation. Current map bytes, actual pieces, side, material, bishop-color/rook eligibility and signed coefficients remain live. Every admitted eligible rook still charges its relation query even if the result is zero (`pawn-piece.md:82–98`). No result/descriptor cache may suppress or combine these charges. FRESH must retain its cache-bypass behavior; fresh per-search clear/cross-iteration retention remains unchanged.
