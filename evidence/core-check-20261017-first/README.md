# Focused core fixture projection check

The single initial run completed all 3,894 planned inspect launches in 4.0004
seconds. Every selected projection passed, with no retries or failed native
exits/collections. This is development evidence, not DIAG transport support,
a mandatory conformance-suite pass, gameplay qualification or performance.

The compact receipt and scope counts are version controlled. The complete
per-launch plan/summary, exact executable and raw streams remain at this local
path; their identities are bound by receipt.json. They are excluded from Git
to keep generated per-query repetitions out of source changes.

The run covers 186 selected source cases from the nine fixture files in
plan.json. Setup, setup-move prefixes, identity and phase compare their declared
fields exactly. Cold pieceSequence is derived only from the actual reported
pieceOrder: king first, then the remaining reported squares in board order.
Influence compares decoded normalized profiles at each ordered queried square;
no relation classifier is implemented in the checker. Activity compares phase,
pieces, activityPressure, weightedActivity and relationQueries, with supplied
activity weights/material. positionTerms and its positionWeights input are
explicitly outside that projection.

Three neutral-root material cases match the CLI's default material context;
values are unavailable. Two square-balance cases use a root placement selected
from released phase fixtures to supply their requested rootPhase. Their current
placement/phase association also comes from a selected released phase fixture;
all 22 phase assertions were executed. This is a declared representability
bridge, not a synthetic square/material evaluator in the checker.

The 285 unsupported source cases are listed individually in plan.json and
summary.json. They cover absent retained-pawn/relation/material-value interfaces
and material/square requests whose supplied values/counts/phases cannot be
represented by this CLI bridge. Supported-case fields omitted from comparison
are listed in each record. Charged influence/square-query totals are unavailable
from inspect and are not invented as zeros. LegalMoves is generated by inspect
but has no compared oracle in this check. Unsupported does not mean passed.

Each raw stdout/stderr pair and comparison is retained under runs/NNNNN/.
Records bind fixture/case/query index or ordered square-query list, exact input,
expected/actual projection, binary/fixture hashes and native exit. plan.json
records checker identity, fixture identities, selection rules and every planned
job. summary.json records every result, unsupported case and completion status.
The exact staged executable is retained; its SHA256 before/after is
54ee2ff1149da5622f0edcc447ae99452834cfa862c62b7e56319a118be2e7a0.

The controller and children used housekeeping CPUs0-5,8-13, with a2-second
per-process and30-second aggregate bound. The parent's affinity was restored.
No CPU14 benchmark, PMU, privileged operation or engine-source modification
was performed. No additional native runs were made after this passing run.
