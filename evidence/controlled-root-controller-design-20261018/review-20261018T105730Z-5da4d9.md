# Controlled root controller: bounded source design audit

Recommendation: extract one native, resumable root scheduling/ranking/retry owner, then one shared timed completion/iteration sequence over that owner and existing `Adaptive`. Keep real child search, random move adjustment, chess PV storage, JSON, and host protocol outside it. For all five routes, also put supplied activity expansion/interruption in a native controlled driver and connect its poll boundary to the production admission. A scheduler plus aspiration/sort scalar helpers alone does not close the two timed routes: it leaves their event admission, capture lifetime and stop recurrence duplicated in the adapter.

This is a design recommendation for parent selection, not an implementation or performance claim. No engine, test, compiler, binary/disassembly, archive or profiler ran in this audit. All helpers used housekeeping `0-5,8-13`. Native/source basis is frozen combined95 `/tmp/imp2-admission-combined95-20261018-n0_cyxa7`; all 13 listed small source anchors were byte-equal to current root at audit. The adjacent anchor JSON binds those files and ten released contracts. No Imp1/private implementation inspected.

## Minimum shared state and transitions

Prefer a small opaque root identity (for example a checked `u16` slot into an immutable external move/label table) so the root recurrence has one non-generic identity domain. Production maps the slot to its actual `Move`; diagnostics map it to supplied labels and reply tables in **initial identity order**, never exploration index. Do not manufacture chess Moves, FENs, Positions, or a `Search` with fake roots for arbitrary labels. Native MoveList capacity is512 (`movegen.rs:10-15`), so a u8 slot/diagnostic64 limit cannot become a production bound. `Move` itself is u16 (`types.rs:169`); a generic `Copy` identity is viable but can duplicate a large body when monomorphized. Parent selects representation; no layout measured here.

Scheduling state, needed across candidates/passes:

- Candidate rows `{id, ranking_score, carried_search_work}`, incoming exploration order and stable score-ranked completed prefix. Existing two-vector production shape can be retained; avoid a third per-node structure.
- Frozen iteration policy, depth, exploration index, previous iteration best, current best initialized -10000, second from prefix or -10000. Keep current best as a real scalar: an all-(-10000) sentinel prefix must not invent a strict best capture.
- Pending candidate identity, original requested window, current attempt window, attempt state initial/retry, and candidate-start absolute search count. The original window survives retry for final ranking penalty. No third pass; first candidate never retries, even at10000.
- Shared work input is an **absolute native `Work` snapshot**, not another production-owned counter increment. Candidate effort commits `N_after - N_before` only upon normal candidate completion and includes both executed passes; prior carried effort is never charged again. Relations advance clock, not root effort/order or SearchID threshold.

Conceptual operations: `begin_iteration(N, depth, previous)`, `schedule_tail_at_second()`, `next_attempt()`, `complete_attempt(adjusted_root_score, absolute_work) -> Retry | CandidateCompleted`, and `finish_iteration()/next_schedule_snapshot()`. Names/signatures are proposals. The owner, not the adapter, decides retry eligibility, window, insertion rank, best/second, strict-best flag and final carryover. Interrupted attempt is a separate completion kind: it cannot enter score/ranking/capture transitions. At most one pending attempt may exist.

rootWorkSchedule invokes the **same** frozen-policy selector and stable pinned-tail operation at their specified boundary without pretending to execute the first search. Sequence diagnostics call the produced state's next-schedule view after completion; that view must not execute another iteration or shift adaptive history. Sort only once, at the native second-candidate boundary; do not pre-sort real production before the first child, since publication/host-error/interruption may occur first.

## Timed completion must be shared, not inferred by the cold driver

Reuse `Adaptive::new/apply` and `Terminal::reason`; do not copy their binary64 coefficients, truncation or stop comparisons. A separate shared native timed boundary must own this exact ordering:

1. Complete all admitted passes; rank the candidate and accumulate carried search work.
2. If first candidate of a **frozen restricted** iteration, apply ScoreDrop using final returned score and fixed previous score. Crossing25000 in an unrestricted iteration does not admit it.
3. If ranking score strictly exceeds current best, install root/child PV, apply BestChange, observe capture metadata and construct its complete snapshot, admit depth>=3 immediate publication, then retain the selected capture at the existing point. Production currently pushes the publication snapshot and performs the fallible host publication before assigning `captured = Some(capture)`; preserve that failure ordering. ScoreDrop precedes BestChange. A later tie never replaces best. Depth1..3 BestChange still increments history but reads no adjustment clock.
4. Record optional diagnostic step at its existing point, then perform root-completion check. A root stop keeps completed work and the selected capture and skips the rest of the iteration.
5. Only after every root completes: choose EasyIteration iff entry was unrestricted and **now** N>=25000; otherwise Iteration. Perform existing adaptive check, then existing Terminal priority, then commit next iteration's previous best/ranked roots only if continuing.

Keep returned score, ranking score and captured score separate. Preserve original sentinel/clamp arithmetic; the two timed contracts use bounded ordinary scores but the production owner does not. `timed.rs:652` calls adaptive iteration check and uses `Terminal::reason()` afterward; preserve that placement rather than adding another observation/early stop merely because `apply` returned true.

The shared timed layer needs retained scalar capture `{id, depth, ranking_score, N, elapsed}` and immediate-publication eligibility. Native chess code retains the real copied root+child PV; cold timed driver uses one label and an empty child PV. Neither adapter may rebuild capture lifetime from final totals. Keep no-capture `None` explicit; workTimed reports selected capture depth (zero if absent), whereas timed reports last executed depth. Finish-time public fallback/deferred post remains in current output/session owners; these controlled routes do not add finish posts.

Do not move all root-controller state into Node/Position/Retained. The ordering owner can remain local to `run_work_timed_inner`; timing must remain reachable by recursive `charge_node -> work_poll` while a child runs. Split a Position-free timing/event core from Clock's root/status/rendering shell, or make the shared boundary accept the existing adaptive state with a static observation hook. Do not hold an overlapping mutable Search/Clock borrow across recursive search or host publication.

A small resumable typed phase enum is one way to preserve the PV/update/publication hooks without placing host/JSON inside the controller: native owner emits the next required action and permits only its acknowledgement before advancing. Drivers mechanically execute `SearchAttempt`, PV-install/capture/publication and observation actions; they do not decide retries/best/stop/order. Alternatively use statically dispatched hooks in a native completion routine. That API/borrowing choice needs a bounded prototype; this memo does not assume the best emitted code. Returning only unordered `{score_drop,best_change}` flags is insufficient: it permits a second adapter-owned event-order recurrence and publication errors at the wrong point.

Adaptive trace must distinguish admitted controller observations from capture-metadata reads. Capture reads are real native ledger observations but excluded from these diagnostic `clockChecks`. Initialization is one read; depth1 root/iteration checks and depth<=3 best-change adjustments read none. Trace the actual observation callback inside `Adaptive::apply`, not synthetic every-event rows. Iteration-completion trace index is candidate count; production check record uses None. This is a presentation projection of one native boundary, not a new clock-read decision.

## Additional workTimed seam

The ordinary supplied-time route needs a native controlled reply provider that advances a wrapping u32 clock only on completed attempted replies; each subsequent observation sees that same supplied time. It must not instantiate a fake Ledger from elapsed input. The workTimed provider instead owns fresh absolute `Work` and an actual native `Ledger`: relation queries first, then search units one at a time, and observations at native admitted events. Only attempted work executes; fractional time accumulates query-wide, never per child.

For workTimed to close interruption ownership without a cold algorithm clone, put that bounded supplied-activity runner in the **native library**. At each credited search unit it calls the same poll admission used by `engine.rs:138-140` and the same Position-free maximum-time check. A tiny shared `poll_due(after_increment_N)` may connect the production charge site, but it alone is not the workTimed implementation; the native activity runner must own chronological expansion, stopping at the exact unit, interrupted pass metadata and the absence of a completed score. No poll at zero, relation-only activity never triggers it, and retry/root/iteration never reset its phase. Do not round per pass or batch blindly past a poll boundary. Optimizing a native controlled runner into poll-sized chunks is a separate decision, not required now.

This is a distinct, small charge/poll admission extraction in addition to root scheduling. Actual production charge sites (`ordinary.rs:479`, Q conditional charge at `quiescence.rs:228`) remain unchanged; resource-node-limit check still precedes charge, and production host command precedence stays in `work_poll`. Shared native pure clock check must not consume/ignore real commands or shift their polling point. Current `work_poll` checks maximum before processing a command; command stop/abort can determine the reported reason. These five no-host routes do not qualify those enclosing host semantics alone.

No further adaptive **arithmetic** extraction is needed: `Adaptive` is already native. Its event admission, observation laziness and resulting stop/capture sequencing must become shared. Keep GameClock/Schedule separate: they allocate persistent session allowance, while `timed::Clock` is per-search and wraps Adaptive+Ledger. The five controlled operations supply allowances and do not exercise game-clock synchronization/reset.

Use exact field sets, integer/bool types, label domains and reply dimensions for each route. Fully validate all queries/iterations/unused retries and suffixes before running the native controlled driver; unused means no execution effect, not permission for malformed fields. Preserve identity-table mapping through reordering and query independence. Do not impose a production2^53 limit or reject/enlarge equal sentinel windows merely because real child-search ingress ordinarily uses proper windows: the controlled scheduler boundary admits them without executing a fabricated legal search.

Phased proposal for parent selection:

1. Extract root owner into native timed scheduling, replacing current decisions at mapped sites, and expose native controlled order/unrestricted/restricted drivers. Verify12+12+41 cases and invariant/differential generated prefixes, unchanged native default tests/strict54/eightwire. This is a valid three-route milestone, not all-five completion.
2. Extract shared timed completion/iteration event owner with static hooks/resumable actions, keep `Adaptive` and `Terminal` arithmetic single-source, add native supplied-time driver. Verify8 timed cases plus targeted threshold-crossing, ordered drop/best, equal ties, no depth1 observation, sole-root and captured-vs-final snapshots. Full engine strict/wire again after source changes.
3. Extract shared actual poll admission and native bounded supplied-activity driver; verify26 workTimed cases, poll exactly at final supplied unit, relation-only clock crossing, retry interrupted, no initial capture and preserved prior-depth capture, wrap and unused invalid suffixes. Independent raw/expected/exit reconciliation and exact source/artifact binding remain necessary.

Before adoption, inspect scoped default codegen only after parent clearance: root row/vector size, extra indirection, stack/frame, helper call traffic, observer/static specialization pruning, whether static child/time hooks duplicate the entire root loop. No vtables, boxed callbacks, per-node fields, new per-child allocations or second maintained chess view. Reuse existing root vectors where possible; a `usize` identity may enlarge a row compared with u16 Move, so do not select that size accidentally. A larger generic full-root driver reduces sequencing ambiguity but risks duplicating a substantial ordinary loop across observer/host/provider combinations, invasive borrow refactors and changes to child/history/host failure ownership. Scalar-only helpers are smallest code change but inadequate conformance ownership. Preliminary ranking: compact root owner plus a shared timed event boundary first; full static driver only if a concrete borrowing/codegen prototype shows a simpler result.

No performance gain is predicted. All99 controlled cases would establish bounded root composition, not recursive activity production, gameplay qualification, every session reset, public text or host interruption behavior. Parent owns architecture, experiment order and any external consultation.
