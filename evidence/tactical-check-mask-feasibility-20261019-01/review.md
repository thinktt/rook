# Tactical direct-check masks: feasible with explicit boundaries

No source/domain counterexample blocks a private coherent generator using reverse checking-destination masks, provided it vacates the moved source and preserves the exact list below. This is feasibility, not implementation selection or a speed prediction. The public `tactical::generate` must remain the unchanged scalar fallback. No new state, permission creator, Influence map or full mailbox/profile conversion is needed.

Current Q calls tactical generation only in its nonchecked branch (`quiescence.rs:296–306`), before ordering and later own-king screening at435. It already holds `geometry_permission()` at268. The guarded native root validates once; Position's set_square updates planes and null preserves placement (`position.rs:245–254,354–359`). Public externally supplied/observed subtree ingress clears the flag before use. Thus that existing geometry authority can justify a private plane path; legal-position assumptions cannot replace it. `Position::validate:431–479` checks canonical lists/mailbox/planes and tags but does not prove the nonmoving king unattacked. Arbitrary public stale planes, aliases, malformed/lazy inputs must stay on old scalar behavior without new eager validation or normalization.

For a quiet destination T of source S, `direct_check:163–197` tests only the moved kind, and scans T→enemyKing while ignoring S. Let O_S=occupancy & !bit(S). For each enemy-king ray, take its empty prefix before the nearest O_S blocker. Their diagonal/orthogonal unions are C_B(S)/C_R(S); C_Q(S) is their UNION. C_N is the existing immutable knight mask about the enemy king. For an empty reachable T, membership in the appropriate C is exactly the old direct test: the segment has no other occupied square. There is no Influence transparency—every intermediate occupied piece is opaque. EnemyKing is the endpoint, not a transparent intermediate occupant.

Source vacancy affects at most one king ray. If S is not its first occupied square, the nearest blocker stays; if S is first, extend only that prefix to the next blocker/edge. Full O_S recomputation is simpler but repeats up to4/8 ray scans per slider source. A node-local base visibility plus one corrected ray is plausible but needs careful ownership/order proof; both are setup costs. The existing immutable rays/knight masks are geometry only (`attacks.rs:12–88`); their Influence-named getters do not license transparent Influence occupancy rules.

Concrete static falsifiers:

- **Vacancy:** existing test `tactical.rs:575–584` asserts R c4→c1 checks kingc8. Old occupancy stops atc4 and wrongly rejectsc1; clearing S is mandatory even in a coherent joined position whose enemy king was already attacked.
- **Checking axis differs from movement axis:** Q c4→d5 checks kingd8 along a file. A diagonal-moving queen must use C_B|C_R, not only the corresponding mover ray family. R a4→d4 vs kingd8 similarly turns axes; B b4→d6 vs kingf4 turns diagonals. Each kind needs ALL of its king-relative check directions.
- **No discovered substitution:** existing a2b4 knight witness at422–424 uncovers rook a1 against kinga8 but is excluded. Testing projected whole-position `attacked(enemyKing)` would incorrectly include it.
- **Opaque blockers:** R a4→b4 does not directly check kingb8 through an own queen onb6. Influence-style queen/rook/bishop transparency or weakened rays would incorrectly admit it.
- **Pseudo-legality:** the pinned e2xf2 capture and unsafe EP at410–421 remain generated; the e1xf2 moving-King capture at448–454 remains. Check masks must not filter captures, reject own-king exposure, or enable capture of the opposing King.

For sliders, movement reach uses the original source ray up to its first occupant; removing S changes nothing on that source-excluding ray. Intersect its empty prefix with C_kind(S), then enumerate qualifying bits nearest→far inside the ORIGINAL direction loop. Increasing linear directions use least-set-bit first, decreasing directions most-set-bit first; guard zero before scans. Append the SAME nearest opposing nonking capture after those quiets. Friendly/opposing-King blockers stop without capture. N retains its explicit eight displacement order; numerical bit order over its whole mask is not equivalent. Source lists stay chronological and type order stays P,N,B,R,Q,K. EP/pawn-check prefixes, prefix deduplication, pawn captures/quiet queen promotions and capture-only King generation should remain byte-for-byte owners, as should the existing push/capacity guard.

The released candidate contract requires those pseudo-legal/direct-only and ordered rules (`quiescence-candidates.md:52–101`). Its standalone setup restriction against an initially attacked nonmoving king at31–37 is not a reason to delete existing broad native/public joined behavior; the private root geometry flag is not that admission predicate. Exact list equality matters before ranking, not only equal sets. N/R/statistics, later eligibility/projection/child/history timing and complete pre-order generation must remain unchanged.

Two scopes have different costs. **Membership-only** retains old empty-target traversal/loads and replaces direct_check replays with mask membership: smaller ordering proof, but it leaves most enumeration and may replace an already-cheap N/alignment rejection with setup. **Construct-only qualifying targets** can skip rejected quiet slider destinations, but pays movement-prefix scans/intersections and ordered bit enumeration; captures and output work remain. N still has at most eight ordered endpoints/capture decisions. Neither scope should eagerly construct bishop+rook king masks for pawn/King-only calls; N-only calls need only a knight mask, B/R need the relevant ray family, Q both. Such categorical/lazy setup is distinct from density/corpus tuning, but adds branches/lifetimes and must be priced.
