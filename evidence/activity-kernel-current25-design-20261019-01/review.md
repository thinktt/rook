# Current25 activity kernel: local category masks and per-piece destinations

**Preliminary judgment:** bulk destination classification is semantically feasible and materially different from the parked trials. The most defensible bounded design is an invocation-local, bit-sliced **category producer plus per-piece destination masks**, using sparse destination-value accumulation and the existing piece-score/pressure/weighting owners. It removes repeated mailbox/Influence/relation classification on destination walks, not complete activity evaluation. It merits a concrete kernel design/prototype only if the parent accepts its construction/consumer cost risk; these profiles do not establish that it will win. Reject an unconditional512-lookup category prepass, a new persistent Influence representation, and a many-popcount weighted dot product as the initial design.

## One concrete replacement boundary

Keep public Activity output and compute arguments unchanged. Keep existing native Influence construction, all other evaluation/search owners, allowances/castling/legal generation and root caches unchanged. Work only inside the pure activity producer:

1. Build one temporary bit-sliced view of the **supplied normalized Influence bytes**, not physical attacker counts or a substitute attack map. Its16 u64 bitplanes encode the two64-byte profiles exactly. Derive multiplicity capped at4 and least-tier predicates from those normalized digits. Build only the tested classes required by present activity kinds; do not build anything when there are no activity pieces. This is a fixed semantic presence gate, not a tuned threshold. Source sum/penalty may keep its existing scalar byte reads.
2. Obtain color/type occupancy masks from actual mailbox tags once. Existing persistent AttackBits is an attractive input only with an explicit coherent-placement precondition. Public Position fields can disagree with private planes, while current activity reads mailbox/lists; blindly consuming attack_view would expand its dependency. The initial self-contained alternative must construct local tag/occupancy masks from the mailbox (and pay for it), without rebind/Session permission, validation per evaluator call or new Node/Position fields. Native chronological piece lists remain the per-piece source inventory. Do not silently change custom supplied Influence behavior.
3. Per color/tested class, derive two category-bit masks for adjusted direct destinations and, for bishop/rook, unadjusted additional destinations. Exclusion is lane-wise **saturating subtraction of normalized packed byte16/4/2**, preserving mixed-radix borrowing; it is not subtraction from independent unlimited physical counts. The original relation definition yields favorable and contested lane masks, unfavorable their complement. Then apply actual victim-type capture priorities and queen exception by exact Piece masks. Category3 must remain distinct for C/T; weak/strong alone loses value.
4. Per actual piece, produce direct D and additional A destination masks, keeping rook vertical Dv/Av separate. Accumulate C and T for that piece, then pass the resulting Mobility to unchanged piece_score_kind. A sparse category-mask walk sums the existing destination table values, with category fixed by the selected mask; it avoids per-destination mailbox/Influence/LUT classification. It need not force a dense population-count dot product. Additional charge is cardinality(A) for **each piece**, independent of categories, opponent0 and capture overrides; vertical doubling affects T only. Select the existing rook value row from the actual opposing king, retaining both gate boundaries.
5. Across pieces of just this color/kind, accumulate Weak = union(D intersect category0/1) and Strong = union(D intersect category2/3). Flush those two masks into the existing fresh byte Marks with the existing type/label bits, then discard them. This deduplicates presence, not mobility or charges. Both masks may contain a square. In particular category0 still makes a weak mark. No A square makes a mark. Existing king_pressure, its mailbox traversal/arithmetic, pressure→shelter handoff and final weighting remain unchanged. This avoids changing the pressure consumer while honestly paying sparse bit scans/byte OR stores; no claim that mark work disappears.

**Exact additional sharing:** knight and bishop final direct categories are identical at every target for the same color/map. Both use minor tier and removal16 and the same capture overrides. Their opponent0 shortcut differs physically, but an opposing-occupied bishop's adjusted relation with opponent0 is Favorable anyway; both adjusted calls charge0. Thus a shared minor direct category mask is sound. Their geometry, per-piece C/T/curve/exemption and additional behavior remain different. This is not permission to share per-piece final scores.

A relation-mask implementation can use the actual Boolean contract: with capped multiplicities a,d and least tiers v,u, favorable is a=0 OR [d!=0 AND v>t AND (a<=d OR v>t+u)]; contested is a!=0 AND d!=0 AND v=t AND a<=d. Each predicate is a64-lane bit mask. Least-tier/t+u combinations are fixed mathematical categories, not personality material values. Deriving masks with ordinary bit operations would replace repeated lookup loads; it does not change the adopted relation table or public relation semantics. A scalar512-lookup fill would generally just move/add classifications and is not the proposed mechanism.

## Geometry and exact accumulation proof obligations

For each slider ray, let P be its geometric prefix through the first occupied square (or edge). D=P excluding friendly occupants. Let X be the prefix through the first **nontransparent** occupied square under this activity kind/color/direction (or edge). A=(X minus P) excluding friendly occupants. These sets exactly reproduce multiple transparent blockers: the first opaque blocker ends the extended ray, opposing endpoints are included and own endpoints excluded. Queen transparency is empty, so A is empty. Bishop opposing pawn/king transparency and rook opposing nonpawn/king transparency are activity rules, not Influence ray rules or legal safety. Own forward rook-ray knight/bishop/queen transparency differs from other rook directions. First/last-bit direction conventions, absent blocker and edge handling need independent proof. Knight D is on-board targets minus friendly occupancy. Rays from one source are disjoint, so set union does not collapse any same-piece ray multiplicity; different pieces MUST NOT union their C/T/A charges.

Per-piece `M=floor(3T/4),floor(T/2),floor(5T/16)`, phase scaling/index clamp, curve, uncapped source profile sums and low-mobility/source-query rules remain in the old owner (`activity.rs:347–385`). Do not round after grouping same-kind pieces. Retain exact C, including categories3. R adds every included additional square, even if overridden or opponent support is zero, plus each admitted low-mobility source query. Computing category masks adds no semantic R, but cannot cancel consuming charges. Side raw scores are summed before the276/256 round; signed material/weight rounds and pressure/shelter composition stay in current owners (`:148–157,484–490`). No charged/poll/history/cache timing site changes are needed.

## Costs, pitfalls and falsifier

The cost includes transposing128 input bytes, constructing mailbox masks, normalized capped-count/least-tier and adjusted views, per-class Boolean masks, ray first-blocker scans, sparse value/mark scans and extra live locals. The128-byte Influence transpose alone does not replace existing consumers' scalar view; retaining both across the engine would add copy/maintenance/decode obligations. A new persistent representation is outside this bounded proposal. Even locally this adds roughly128B of profile planes plus occupancy/category/destination temporaries beside current128B Marks; compiler register/spill/frame/copy behavior must be measured. No zero-construction or copy-neutrality claim is justified.

Base target is x86-64, not POPCNT/BMI/AVX. Existing closed25 captures show software population counts; a dense weighted sum using six destination-value bitplanes and multiple category popcounts can add many such expansions per piece, especially bad for a knight's <=8 targets. Sparse walks of existing V avoid assuming hardware popcount; cardinality/first-bit operations still have costs. No target-feature change belongs in this proposal. Endgame08's much smaller mapped destination bands make fixed setup particularly dangerous. Unknown frequency of active classes/target reuse prevents an amortization claim; raw Ir does not supply those denominators.

Before a production trial, falsify the kernel in isolation with full construction/mark-flush included and inspect lowering on the actual baseline target. Stop if relation-mask construction degenerates to scalar512 lookups, weighted aggregation proliferates software-popcount helpers, or geometry/input conversion remains alongside unchanged per-target classification with no real substitution. A later integrated original fixed prescreen must pay every invocation's construction, including sparse/pawn endings; a loop-only microbenchmark omitting setup would not answer this question. If parent needs a denominator first, only actual active-class and direct/additional endpoint demand per invocation would resolve amortization; no new census framework is proposed or built here. The current mapped pool establishes relevance, not profitability.

Future meaningful correctness tests: exhaustive256x256 normalized-byte pairs packed across lanes against the unchanged independent digit model, all three removals with saturation/borrowing, full category values including capture/queen overrides; independent coordinate D/A/T/C/marks/R oracle with chained transparent blockers, both rook directions/gate edges, opposing kings, promotions/broad placements and chronology permutations; category0 weak and simultaneous weak/strong marks; same placement/custom Influence and stale private-plane public Position witness if mailbox-owned input is chosen. Existing direct/category, extra-ray, rook, low-mobility, pressure-presence and signed-round tests (`activity.rs:548–772`) are useful fixed witnesses but share current helpers and do not prove a new set algebra. The10000 current Influence oracle is not an activity oracle. Preserve all existing tests and compare complete Activity plus downstream shelter, not only mobility masks.
