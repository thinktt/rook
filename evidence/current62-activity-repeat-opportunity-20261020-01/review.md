## Actual lifetime edges

* **Ordinary scout retry:** ordinary.rs:1006 constructs one child; :1036 searches it, then :1042–1059 can search the same mutable child with a wider window. History is popped only at :1066. Position is unchanged while Retained may be refreshed (explicitly tested by :1045). Each invocation has its own map scratch (:778), and FULL is :812. TT cutoff (:750–763), FAST return (:780–808), draws, errors or a Q handoff can prevent either FULL. A scout retry counter is therefore not a duplicate-Activity counter.
* **Timed root aspiration retry:** timed.rs:609–614 constructs one ActualChild; timed_sequence.rs:44–59 retains it across `Returned::Retry`, and timed.rs:619–625 searches its same Node. The retry condition is root_schedule.rs:143–154. This is another conditional repeat within one child lifetime, not reuse across iterations. Each new candidate/iteration calls begin_candidate again.
* **IIO is not that lifetime:** ordinary.rs:1099 takes the parent immutably; each pass/candidate creates a new child at :1151. A later pass or main search (:1006) recreates a child even for the same move. A per-Node memo does not span these objects.
* **Root and Q:** quiescence.rs:138–158 binds/reset context and FULLs a fresh root once. begin_owned_sequence (:199–205) resets ledgers, not an Activity memo. Normal root iterations search freshly made children, not FULL on the root again. Ordinary hands off to Q at ordinary.rs:719–736 before its own FULL. Q's selector is called once per nonchecked invocation (:267–283); evaluator.rs:661–704 permits sparse FULL or FAST followed by one refreshing FULL, not two Activity calls. Q child preparation (:408–426) only probes replies; recursion (:442–463) uses that child once. Checked Q omits the standing selector. Separate repeated invocations remain possible through the two retry scopes above.

## Exact reuse premises and live work

Activity's explicit inputs are Position, the supplied Influence bytes, root-produced material score and effective mobility weights (activity.rs:94–101; evaluator.rs:191–223, :390–401). It reads typed chronological N/B/R/Q sources, mailbox occupancy, king locations, phase/endgame and fixed tables, then creates fresh marks, piece totals, pressure, weighted result and relationQueries (:102–156). Board equality alone is not a proof of all these inputs. Same owned child with unchanged Position is a stronger source-level premise; no parent/child restoration occurs across the retries. Root material context and weights remain bound during the actual owned native call, subject to the existing native ownership proof; arbitrary public Evaluator/Host use is not thereby sealed.

`in_check`, bounds and Retained P/G are not Activity inputs. Both colors' pieces are produced; current side selects live FULL tempo later (evaluator.rs:432). Null changes side/rule state and creates a distinct Node (:93), so it must not inherit an Activity memo merely because placement matches. Ordinary children change placement; new roots/parameters require new context. No reuse across child recreation, null, go, public mutation or arbitrary supplied maps is established here.

The geometry permission validates Position, **not native map provenance**. Public Some maps remain authoritative (evaluator.rs:306–335), and public full/fresh/observed/select routes can be called with different maps or mutable root context. A cache inside generic public FULL keyed only by Node identity, age or geometry permission would be unsound. Restrict any later hypothesis to a source-proved private native map construction and the same owned retry scope, with public/custom/observed bypass. FRESH pawn selection and observer ordering must retain their existing behavior; there is no permission to canonicalize stale public state or suppress a lazy panic.

Memoizing Activity alone must still perform each FULL's PawnCache selection/replacement, pawn terms, progress, central influence, shelter using the produced pressure, patterns, material/tempo/finish, Retained writes and full/stat/observer effects (evaluator.rs:389–476). PawnCache can change in descendants despite identical Activity inputs. Replay the original Activity relationQueries on every logical FULL, together with the live pawn charge. EVAL-ACTIVITY:181–182,212–220 and EVAL-RETAINED-SEQUENCE:55–65,99–107 require current components and repeated logical charges; EVAL-FRESH-SUBTOTAL:128–136 gives the composition. ## Cost import, alternatives and prior work

Activity holds two i32 piece totals, two i32 pressures, one i32 weighted value and u64 R (activity.rs:10–15). That is 28 bytes of scalar fields **before layout/padding/validity metadata**; no actual sizeof or emitted-copy claim is made. Node and Retained are Copy, and child/null inherit Retained. Adding a memo there increases copies and requires invalidation on every construction/public mutation; existing P/G/nonking/age fields neither contain nor authenticate Activity. No Node payload is proposed.

Per-call storage gains nothing where that invocation FULLs once. A per-ply slot is not a lifetime proof: descendants, IIO and different children reuse plies. An ephemeral memo owned beside the exact retry child could avoid persistent Node growth, but needs private routing/lifetime across ordinary/Q and evaluator calls, validity state and extra arguments/stack/copy costs. Those costs and emitted factoring are unknown; the failed split-boundary experiment47 warns against assuming a source-local saving survives ABI changes. No such seam is implemented or selected.

Decisions0014 and0024 already parked global exact-placement pure-component and root-bound weighted caches after own-PGO failures. They skipped Activity plus shelter with lookup/key/storage and factoring costs; their placement-hit counts do not count this narrower same-object opportunity. Decision0042 declined within-one-Activity category caching; its target-repeat percentages likewise do not measure FULL retries. This review does not reopen those variants or transfer their costs/results to current62.

A bounded future diagnostic would have to count actual Activity producer executions in each same-child retry scope, distinguish first/retry, ordinary/root/Q/no-FULL exits, and verify unchanged complete numerical inputs and native-map provenance. It must leave all producers and logical work live. Recreated IIO children and foreign/public calls must remain separate, and counts would still not price storage or routing. Until those quantities exist, defer a cache prototype. No occurrence, whole-owner removable envelope, speed forecast, conformance closure or native runtime observation is claimed.
