# Wrapping bit-sliced Influence accumulation: bounded feasibility

The algebra is feasible and distinct from the existing producer, but current evidence does not justify selecting an engine trial. The missing discriminator is a sufficiently cheap accumulation/output lowering with acceptable register pressure. There is no new candidate, source change, or speed prediction here.

**Owner and history.** Current coherent.rs:28–76 owns scalar P/N/K emission followed by per-color B/R/Q masks and ColorSums. slider_masks:100–140 remains the numerical geometry owner: occupied endpoint inclusion, own matching sliders/enemy king transparency, own queen weakening, and forward-pawn extra square stay unchanged. ColorSums:143–180 is the replaceable accumulation representation. The prior experiment35 bit-sliced *activity classification* design consumes already normalized Influence; it is not this producer or a measured bit-sliced wrapping sum. Targeted own research/decisions and the original37 kernel review contained no prior trial of this accumulator. This is a bounded history check, not an exhaustive evidence-tree census.

**Exact addition.** Let B[0..7] be u64 planes with bit t equal to bit b of target t's byte. Initially all planes are zero. To add target mask M at contribution shift s, repeat b=s..7: old=B[b]; B[b]=old XOR M; M=old AND M. Drop carry after b=7. Each target is an independent ripple-carry adder modulo256. Weights weak/queen/rook/minor/pawn are 1/2/4/16/64 (s=0/1/2/4/6). By induction after each source every target equals its ordinary physical weighted sum modulo256; the released normalization is exactly this mixed-radix byte (evaluation-relations.md:15–23,79–82). No per-category saturation, deduplication, or carry suppression is permitted. Different sources remain separate additions; source-order commutation is specific to these placement sums.

For one slider, N and W are disjoint by the unchanged masks owner. If W is nonzero, first carry W through planes0..s-1; at plane s OR in N, then finish the single carry chain. The low carry is a subset of W and cannot intersect N. This reduces the combined source to one eight-plane chain plus that OR; it does not merge overlapping different-source masks. Weak=0 can start at s. Final plane7 needs XOR but no unused outgoing AND.

**Exact output transpose.** With little-endian target order a1=bit0, perform three stages on eight words a=B, s=4,2,1 with masks respectively 0x0f0f0f0f0f0f0f0f,0x3333333333333333,0x5555555555555555. For every i with (i&s)=0 and j=i|s:

```
t = ((a[i] >> s) XOR a[j]) AND mask
a[j] ^= t
a[i] ^= t << s
```

There are four pairs/stage, twelve pairs total. This exchanges plane-index bits with target-within-byte bits. Afterwards word a[j]'s bytes are target bytes j,j+8,...,j+56. A final 8×8 *byte* transpose is necessary; omitting it silently permutes squares. Baseline SSE2 suffices: load eight words into low halves; four unpacklo_epi8 pairs; four unpacklo/hi_epi16; four unpacklo/hi_epi32; four unaligned128-bit stores. Exact indices/network are in model.py. Output vector0 holds targets0..15, then16..31,32..47,48..63. No new lookup table or higher ISA is required. The twelve word swaps are 72 abstract scalar shift/XOR/AND operations before register moves; the byte transpose is twelve unpack operations plus eight word-to-vector inputs and four stores. These are algorithm inventories, not actual machine instruction counts.

**Leapers and domain.** attacks.rs:13–17,21–63 already stores knight[64],king[64],pawn_sources[2][64]. Knight/king destinations use their symmetric masks. Pawn targets for side c are pawn_sources[1-c][source], since the stored row uses the attacker's backward step. A narrow immutable private getter would suffice; no new maintained state or large static table is needed. The model independently checks all64 squares/both pawn colors against coordinate offsets. Native source inventory would remain chronological. Such access is only for the existing coherent private path; public build/custom maps/invalid-state fallback and current root proof must remain unchanged. A mask is not legal-move geometry and must not omit pinned pieces or occupied targets. No relation charge belongs to Influence construction; all native R consumers and timing/None-to-Some demand remain untouched.

**Bounded cost inventory and risks.** Current weak0 slider emission has eight EXPANSION scalar loads, four vector forms, four vector shifts, and four wrapping byte adds per source. Nonzero weak doubles expansion loads/forms and adds four vector ORs. New fixed-chain logic is seven Boolean operations for a weak0 bishop, eleven rook, thirteen queen; a weakened slider takes fifteen plus the disjoint-mask OR. These omit extraction, mask materialization, moves, control flow and scheduling. Pawn and knight masks take three and seven Boolean operations; king takes fifteen, versus the current at-most2/8/8 target byte additions respectively. All masks still have to be fetched/formed. Final transpose/setup is paid per color, not per source.

Crucially, current ColorSums keeps four XMM accumulators while slider_masks uses scalar GPRs. Eight new scalar planes have the same64-byte footprint but a different register class. They coexist with normal/weak masks, carry/old temporaries and occupied/side/kind/ray/scan state; spilling between sources or across slider_masks could defeat the apparent lookup removal. This is a concrete risk, not an observed spill claim. The 72-op word transpose and twelve-unpack output also cost something when only one slider exists. With zero sliders current build skips all vector setup; an all-source bit-sliced version still pays its eight-plane/output machinery for P/N/K. Sparse/endgame and full construction costs therefore matter independently of dense slider overlap. No density dispatch or hybrid is proposed.

The parent's approximately1.64%35 mapped emission context is not an avoidable bound: required output accumulation remains, source mappings mix loop/setup, and neither total masked emission nor per-source register costs have been remeasured here. No whole-engine gain follows from this algebra or abstract operation comparison. Before selection one would need evidence that a concrete baseline scalar/SSE2 lowering avoids per-source spills and keeps zero/one-slider construction competitive, with full128-byte producer parity. No compiler, binutils or runtime evidence was acquired for that question.

Pure Python success proves the proposed arithmetic/transpose model, not performance, compiler lowering or native integration. Recommendation: retain as a distinct algebra question, NO-GO for an engine experiment on present cost evidence.


**Prospective categorical zero-slider boundary (not selected).** The parent's proposed split is semantically feasible within the existing coherent-only builder: obtain each color's B/R/Q slices, test whether all are empty before emission, retain exactly scalar P/N/K emission for that color when empty, and use bit-sliced *all-contributor* accumulation otherwise. This is inventory presence, not phase/corpus tuning. A single selected path finishes the color's byte output before any consumer; there is no relation charge, observer or callback between source contributions. The private coherent precondition makes moving this pure inventory decision earlier safe; it must not alter public scalar malformed-state behavior. No Node/Position state or persistent map is needed.

The zero-slider branch avoids fixed transpose work entirely and preserves the existing efficient categorical case. It does not solve the one-slider case: that color pays plane initialization, complete output transpose, and scalar-GPR competition across P/N/K plus slider processing. The parent's mapped contexts are emission1.643%35/.195%08 and leapers1.411%35/1.044%08; these are supplied attribution contexts, not rederived here or removable-work bounds. Without color/inventory-conditioned dynamic attribution they do not establish how much leaper work reaches the bit-sliced branch. No new census or profiler run is warranted by this algebra memo alone.

The split also creates two representations of leaper emission: scalar bytes on one branch and bit-plane additions on the other. Retaining type-specific loops/geometry exactly may duplicate private loop bodies or require emitter specialization; neither code sharing nor inlining/frame neutrality follows. An avoidable per-target runtime selector would undermine this purpose. Eight live scalar planes remain the principal backend risk; the fallback does not fix that. Explicit future gates would therefore need actual branch/producer selection, output parity and scope, register/spill/frame effects, and output-transpose lowering before any timing decision. This narrows a possible future discriminator but does not itself select43 or reverse the present NO-GO for engine experimentation without that evidence.
