# Unselected two-phase scalar Activity traversal

Source feasibility is positive, conditional on retaining the exact lazy iterator and all numerical calls. This is a compiler-first question, not candidate selection or a speed forecast. Current canonical and frozen57 Activity are byte-identical. `activity.rs:269–343` remains the public scalar numerical owner; the released activity contract sections “Direct destinations and additional rays”, “Potential king-pressure marks” and “Work accounting” explicitly separate the two phases.

For each existing source/direction, the state starts direct. Every visited square is fetched once, in the existing ATTACK_RAYS near-to-far order. If opposing or empty, evaluate it in the current phase before deciding continuation. An occupant then either stops or is transparent and transitions to additional. Additional is monotone and never returns direct. Therefore two consecutive loops over ONE iterator are equivalent: direct loop consumes the first transparent occupied square completely, then additional loop starts at its successor. No restart, peeking, prefetched next victim, or second endpoint classification is allowed. Empty rays and transition on the final square must remain natural zero-iteration cases. No bitplanes/coherence permission is needed; actual mailbox and supplied Influence remain authoritative.

The direct endpoint remains direct even when it triggers continuation: opposing bishop/rook targets execute adjusted relation/shortcut/capture rules, add C/T and mark weak or strong (including category0). Own occupants never classify, mark or contribute, but an own transparent blocker starts the additional loop. For B, every opposing type is transparent; own N/R are transparent. For R, opposing nonpawns and own R are transparent, with own N/B/Q additionally transparent only on that color's forward vertical ray. Reapply exactly the existing transparency function at every later occupant. Opposing opaque endpoints contribute in their current phase before stopping; own opaque endpoints stop without classification. Thus opposite colors and reversed rays need no changed policy.

Queen has no transition: its transparency result is always false, so the direct iterator stops after the first occupant and any additional loop is unreachable. Prefer compile-time erasure of that loop, not a new runtime special case. Knight is untouched. Preserve each numerical expression/cast and update sequence: direct C and presence marks, T, then transparency; additional increments one R before unadjusted relation/capture priority and T, never C/marks. Vertical rook factor2 affects only T, not C/R. No charges are coalesced, no category is cached, and each source finishes its original piece-score calculation. The old contribution weight at the transition square is preserved by doing classification BEFORE changing phase. Source support/curve/low mobility, king pressure, weighting and shelter are unchanged.

Public lazy behavior is a separate constraint: preserve original Piece decoding and supplied-map reads only where the old path performs them. Do not precompute a blocker list or scan beyond an opaque stop. A malformed tag hidden past such a stop remains unobserved; one on an actually decoded path must fail as before. This is conditional source equivalence, not a new promise that all malformed inputs succeed or retain identical panic partial state. No public admission is narrowed or widened.

Compiler discriminator: in actual emitted B/R paths, direct and additional backedges should no longer carry/test a phase flag or merge the two numerical paths. Queen must not acquire a continuation path. Reject the hypothesis if LLVM already versions the original loop, remerges the split, or duplicates enough common victim/value/transparency code to add harmful register pressure, frame/spills or code size. Same-frame alone is insufficient, and fewer branches alone is not a gain claim. Existing51 source-line attribution gives83,089,756 simulated SELF Ir at line311's phase conditional (~0.1884% of44.100B), not its branch count or a wholly removable envelope. Adjacent victim/loop/arithmetic rows retain necessary work and cannot be added as savings. This aged51 annotation is not current57 CPU or PGO lowering evidence.

Small non-tautological controls if selected later: (1) an independent coordinate walk derives ordered direct/additional visits and complete C/T/R/marks for both colors, all B/R/Q directions, first occupant at each distance, every own/opposing kind and repeated transparent chains; no reuse of the split iterator/production masks. Include no blocker, endpoint-only, forward/backward rook and edge cases. (2) custom all-byte support strata force distinct adjusted/unadjusted outcomes and category0/3 capture marks; compare C/T/R/marks and composed Activity/pressure/shelter, preserving vertical doubling and overlapping weak+strong marks. (3) stop/lazy falsifiers place an invalid tag immediately behind an opaque blocker (no visit), and on a reached decoding path (same failure), including friendly short circuits and queen no-continuation. Existing full coordinate oracle and original tests remain independently useful; tests merely forwarding both routes into the same new helper would not distinguish a phase-boundary error.

This is distinct from52's separate scalar/coherent consumers and mask geometry (generic park after larger coherent frame/code),56's paired support arithmetic (own-PGO park), and category-census/cache no-go. It introduces no new data representation, persistent state, lookup/cache, supplied-map bypass or permission creator. No previous timing result transfers. No prototype/runtime is selected or executed by this review.
