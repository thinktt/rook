# Full-evaluation reuse opportunity probe

A separately identified D=true ordinary-wire derivative adds diagnostic counts
and writes them only to a supplied private file on normal quit. It completed
all54 unchanged public profiling replay cases with exact outputs and work.
This binary is not production and none of its timing is used as a CPU result.
The frozen source/build archive is in the sibling build folder; the manifest
and every raw counter/oracle report are retained with hashes.

Across the54 fresh searches, full evaluation ran37,094,821 times and entered
with retained age0 on18,569 calls (0.050058%). Those counts include first-root
full evaluation and are an opportunity estimate for re-evaluating the same
produced node. Only75,340 of121,779,933 full-evaluation relation queries were in
that age0 population;72,590 of115,801,217 activity queries were there.

This evidence rejects the proposed same-produced-node full-component cache as
an attractive next optimization. No cache was implemented. Age0 alone is not
a complete cache-validity key, and these counts neither bound all possible
transposition/pure-component reuse nor claim an exclusive CPU share or speedup.
Root/PawnCache side effects and semantic charges still require their exact
contracts. Invocation totals, source identity and actual replay parity are the
result; these are not PMU counts or a final performance comparison.
