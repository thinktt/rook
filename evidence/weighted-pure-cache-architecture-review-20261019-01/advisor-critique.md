**The proposed static permission can implement a sufficient seal for one blocking, freshly bound search. I found no missing numerical dependency in the stated weighted payload under coherent placement, native Influence and an unchanged bound context. The qualification is architectural: a private const Boolean selects a call path; it does not itself prove the binding's lifetime or the map's provenance. Those remain two independent invariants of the private call graph.** Public root mutation between calls is compatible with this design if every new permitted entry binds and invalidates before its first cache access.

Read the request, feasibility review, current timed/Session/Host paths, root binding/material calculation, full/selector/Q routes, activity/shelter producers and released numerical contracts. No implementation, builds, tests, engine runs, profiling or static-cost collection. Decisions remain yours.

1. **State the seal as an ordering and reachability invariant.** Every cached lookup AND insertion must descend from the fresh entry on the same Search, after successful binding and complete invalidation. No intervening root/weight mutation or rebind may occur before its last permitted access. Other entry paths must neither create permission nor recover it from stored contents. Internal recursion, IIO and scout retries propagate that same permission; none independently manufacture it because they happen to be internal.

The current topology supports this: `run_work_timed_inner` prepares once, and Host callbacks receive no mutable Search/root reference. RootContext and Weights are owned values, not shared mutable handles. Safe external code cannot concurrently mutate them during the blocking borrow. I found no current internal rebind in that interval. Publicly replacing Evaluator or modifying its root after return therefore does not require a persistent epoch signature, provided the next permitted entry always establishes a new binding and clears storage.

The Boolean is not a compiler-enforced lifetime token. A future internal helper could still call a true specialization on an arbitrary Search or after rebinding it. Keep the sole permission-creating entry and the propagation edges small enough to audit. If that becomes diffuse, a private scoped interface tying cache access to the bound context is a reasonable alternative; it is not necessary to demand that extra abstraction now.

2. **The permission does not also certify the map or placement.** The current `ensure_influence` accepts an existing Some without checking its source. Neither ROOT_CACHE=true nor “called from inside search” repairs that fact. Each permitted full/selector route must receive the corresponding native map or invocation-owned scratch whose only producers establish it. A public supplied map must bypass both lookup and population, even if its placement matches a valid cached entry.

There is a separate ingress premise: Position exposes board/counts/starting_units publicly, while `run_work_timed` does not validate their consistency with private planes. A fresh timed call is consequently not a coherence validator. Your coherent native domain is sufficient, but the API claim must retain that precondition or originate permission specifically from an ingress that establishes it. This is not a request to support malformed constructed Positions or add per-hit validation.

Current private search bodies call public `full` and `select_noncheck` wrappers. Keeping those wrappers statically false is correct for public safety, but permission must then reach distinct private implementations on the intended internal paths. Otherwise the prototype can silently lose Q or root reuse; making the shared public wrapper permissive to recover it would reopen the provenance hole. Keep ROOT_CACHE independent of the existing FRESH, diagnostic and IIO decisions.

3. **The dependency closure and payload are sound within that boundary.** Equal coherent placement fixes native Influence, activity pieces/pressure/R, shelter terms and current phase, including starting-square occupancy. Fixed root values/counts/side/average_depth plus current counts fix material; fixed color-owned mobility/shelter weights then fix the two weighted outputs. Average depth is the bound parameter, not changing search depth. Descendant side, rights, EP, history and chronology add no dependency to those stored outputs.

Preserve activity and shelter as separate already-rounded contributions: their material adjustments have opposite signs and their intermediate floors differ. Keeping both raw piece totals is necessary for live side/check-dependent tempo. The proposed 24-byte field total is consistent with that contract; it does not imply smaller aligned entries or stack transport. PawnCache effects, the other terms, semantic R, retained writes, observers and the single finishing operation remain live as proposed.

4. **The unwind argument works without cache cleanup on exit.** Once the blocking call unwinds, no stored permission survives. Old or partially populated data is harmless to statically false wrappers, and the next true entry invalidates it before access. Binding/clear need only precede the first permitted evaluation; an error before any permitted access need not clear unused old contents. If root full is cached, clear must precede it. Work-counter resets within the same bound search are not new cache epochs. This argument concerns cache access only, not recovery of every existing Search field after panic.

The consequential falsifiers are: populated search A followed by public root/personality mutation and standalone full/selector calls; interrupted or unwound A followed by a fresh search B whose placements repeat; and public prepare-root followed later by a selected/observed subtree. None may inherit A's permission or populate entries for later permitted consumption. Within one binding, equal-placement visits with different side/rules/retained/pawn-cache history must reuse only the pure payload while preserving each call's live effects. These are proof witnesses, not tests I ran.

Removing a 790-byte helper's call and reducing payload fields does not establish the dynamic saving or remove the old frame growth. Static propagation through large recursive bodies can change inlining, code size and frames, while misses still pay lookup/insertion. Keep one numerical evaluator body and make access policy the varying part; if sealing requires duplicated evaluation logic or extensive root-context copying, parking remains preferable.
