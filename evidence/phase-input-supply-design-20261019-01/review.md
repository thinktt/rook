## Exact supply path and obligations

Frozen Wstatic evaluator.rs390 already derives Phase, then401 calls public activity::compute and402 shelter::compute. Their activity.rs101 and shelter.rs61 derive it again. A minimal full-only design is private activity::compute_with_phase(...,Phase) and shelter::compute_with_phase(...,Phase), with original public compute signatures forwarding their own actual phase. Full passes its existing local Phase at original call sites. Keep one numerical body, debug assertions, output fields, rounding, PawnCache/R and all observations/order unchanged. Activity needs full Phase for piece endgame scoring and phase-weighted composition; passing only endgame would be insufficient. Shelter's composition retains its complete actual phase input. Public explicit-phase diagnostics elsewhere must keep honoring supplied independent values; no new public phase override is implied.

Any finishing reuse is a separate extension: finish_observed currently calls position.phase().endgame for endgame::finish at501 and again for late flag511. A private finish_with_endgame path could accept the existing current endgame value while the public/fast wrapper derives its own, but cannot assume two derivations currently survive. Preserve observer callback order and the exact final fields. Passing/staging a six-byte logical Phase or an endgame scalar has real ABI/register/stack/liveness/copy implications; no one-register or frame-neutrality claim follows. Whole full/leaf instantiations, outlining and public wrapper costs need actual final-source backend evidence before a future comparison.

Phase must remain exactly current Position::phase362–384 on raw counts and starting_units: sum raw counts, carry N→B→R→Q in base16, discard top Q quotient, material>32 gate, exact opening/endgame clamps and middle residue. Do not substitute root.phase, material balance, normalized actual-piece counts, AttackBits, fresh mailbox reconstruction, a validated-only path or a maintained field. Legal/promoted/current and root phases can differ; public incoherent raw states must preserve the same current semantics. Released root-material-context.md19–50 and position-score.md44–77 distinguish this phase normalization/current phase from root values.

RootContext::material reuse and fast→full reuse are item5's broader independent concerns. Fast may end without refresh; do not eagerly construct full inputs for skipped paths. Material uses fixed root values plus its own count/bishop/depth adjustment and is not the phase material measure. King-square balance also has current-phase dependencies. No combined material/fast/finish redesign, persistent cache, layout field or new numeric policy is proposed. Mutable retained refresh changes positional/pawn/age, not the immutable Position within a full invocation, so scoped pure phase reuse itself is admissible.

Current evidence supports feasibility, not priority or a repeat of26.
