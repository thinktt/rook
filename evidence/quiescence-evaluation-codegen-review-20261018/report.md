# Qnative default selection — bounded static codegen diagnosis

The original Qnative observation/disposition proposal changes ordinary quiescence code generation substantially. Its `visit_q` grows from 7,450 to 9,927 bytes (+2,477) and local stack reservation from 0x4a8 to 0x508 (+96 bytes). The prior two calls from that function to the shared out-of-line full_impl disappear; the new caller contains expanded native full/fast evaluation work. Four helpers are emitted only in Qnative: endgame::finish (333 bytes), RootContext::square_balance_from (231), pawn_progress::structure_weighted (201), and PawnCache::select (295). Whole .text grows 3,568 bytes: +2,477 visit_q, +1,060 new helpers, +31 alignment/padding. All 829 previously matched function symbols retain their sizes except visit_q; Qnative has 833 such symbols. This is a concrete code-shape/frame change, not evidence of zero overhead and not a CPU-cost measurement.

The evidence supports changed inlining/call partitioning around the default observed-selection seam as the immediate issue to address. Ordinary selection originally called self.full/self.fast; Qnative defaults enter detailed-observer call wrappers even for no-op observers. Those wrappers reach different generic call contexts. Source-level condition/order equivalence does not constrain LLVM's inlining choices. The disposition helper was extracted in the same build, so this two-image comparison cannot attribute every instruction or stack byte exclusively to one edit. The helper name/size accounting and lost full_impl callsites strongly favor call-partitioning changes over interpreting the whole growth as an enum dispatch cost.

Out-of-line full_impl remains 2,415 bytes with the same 0x138 local frame; visit_ordinary remains 7,983 bytes with the same 0x428 local frame and one shared full_impl call (0x3eb16 -> 0x40600 versus 0x3f906 -> 0x413f0). Their displayed instruction shapes match after replacing link-address/RIP references, while visit_q does not. This normalization intentionally drops data/GOT referents, so it is only an instruction-shape observation: it is not byte equality or a semantic equivalence/zero-copy proof. Before the inspection cutoff no per-function raw-byte hash or complete GOT/data referent resolution was captured. Accordingly, no semantic equality claim relies on normalization; referenced data targets remain an explicit limitation. Full raw nm/objdump/section/size output is retained for a later authorized follow-up if needed.

Native Node/Retained/Evaluator layouts did not gain fields in the source change. No observer/FullDetails/select_noncheck/fast standalone symbol appears in the captured ordinary nm inventory, but that absence is not an erasure proof: work can be inlined. In particular, the larger Q caller/frame prevents asserting that every temporary detail construction/copy erased. Captured output shows the shifted full/fast/full call partition and additional stack reservation; it does not establish which of those 96 bytes are simultaneously live native component/finish temporaries versus any observer relay payload. The private no-op default must be restored to its original call wrappers and then compiled/reviewed before claiming erasure or a cost improvement.

The proposed bounded correction is a shared private select_noncheck_impl<const OBSERVE: bool,F,G> body. The default uses false and the original self.full/self.fast wrappers; detailed selection uses true and the existing detail callbacks. Only the three evaluation-call expressions are const-gated. Sparse admission, native produced finished fast score, strict window/capture refresh, lazy influence, output flags, ordering and relation work remain in one body. This is a reasonable source-level target for the observed generic call-context change. It does not guarantee the former monomorph/code layout: compiler inlining decisions must still be checked once the parent clears execution. No runtime flag, hot-state field, duplicated adapter policy or new finishing formula is needed.
