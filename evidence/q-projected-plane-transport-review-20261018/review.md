Domain and lifetime limits

Broad joined EP must remain broad: tactical.rs:40 admits an empty target with an actual opposite-color nonking victim behind it, including a nonpawn victim, plus an eligible source pawn in the specified target geometry. Neither transport nor its tests may silently require ordinary pawn-victim ancestry. Node::child and Position use that actual victim and square for retained/identity/list updates. Projected EP removal uses position.side; placement uses mover.color(); their equality relies on the existing generated-mover color invariant. Do not normalize raw rights/EP or add a new gate. The exceptional king-victim cold ingress method remains separate and receives no handoff in this scope.

Unsafe pseudo-captures and pinned quiet/capture promotions remain observable before legality through optimistic best and existing reply/history work. No early safety check or early complete child construction is justified by this proposal. Promotions must preserve actual result tag, group order and root-square delta, including underpromotions in legal evasion/default paths. Current noncheck tactical producer emits queen promotions and no castling; checked legal evasion path retains default placement. A general projected-child API would nevertheless need correct legal castling handling or an explicit internal caller-domain restriction, because projector and placement derive rook home by different native scalar expressions. No broader move or position admission follows from this memo.

Projection lifetime is one exact immutable parent plus one exact candidate movement, before parent state changes. Copy/retained refreshes do not change placement, but another candidate or a child/grandchild projection cannot be substituted. Noncheck history push must see complete coherence even when a reply probe occurs before final own-king rejection. The prepared Node must continue to be reused after any retained evaluation changes; reconstructing it would lose existing state. Outer ordinary scout retry (ordinary.rs:756..816) already retries the SAME constructed child, preserving any refreshed retained evaluation. A Q-only handoff does not imply a second child build per scout retry and must not be extended to ordinary frontier/mate/scout construction merely because they also call Node::child.

Minimal alternatives, in increasing scope

1. Keep the current owners. This remains the default until phase2 generic/own-PGO evidence is understood. There is no evidence here that the remaining maintenance is material.
2. Limit a future experiment to the existing reply-prepared site. It already lies inside the projected view's lexical lifetime. This avoids carrying an Option<AttackBits> across the checked/noncheck join, but leaves the unprepared final child on its current path. It is a smaller experiment with incomplete reuse and still needs the same native placement seam.
3. Cover both noncheck child sites using one crate-internal native projected-child entry, preserving default child API and a shared retained-delta owner. Inside Position, a private statically selected maintenance mode could omit ONLY attack_bits.replace in the exact shared set_square/apply body, then install the supplied view before the copied child leaves that owner. The default route must retain its existing call behavior, not receive a runtime optional view or a hot flag. A generic FnOnce placement builder could share Node's retained body while selecting normal versus projected placement, but changed monomorphization/inlining is a real code-size risk. A same-purpose small shared retained helper is another source arrangement; neither is approved by this memo.

For option3, Q must keep child construction at the current sites. Passing the local view to the final lazy child requires either carrying optional view state out of the noncheck block, or arranging checked/noncheck child expressions around their existing screens. The first may add a discriminant/copy/spills and longer register/stack liveness; the second may duplicate child-selection code or alter inlining/block layout. Passing a 32-byte Copy value, borrowing it across a closure, or storing it in an aggregate can each cost more than the removed plane updates. Even if a compiler removes the data copy, two shared-body monomorphs and expanded placement code can grow Q or ordinary/default code. No allocation, persistent field, layout change, new table, dynamic dispatch or reconstructed second view is needed, and none is justified.

Do not implement normal Node::child followed by overwrite as a claimed optimization; it preserves duplicate updates. Do not move full child construction before current route/eligibility/reply decisions, or defer the reply child until after own safety. Do not duplicate apply_unchecked/retained algorithms to avoid a seam. If skipped maintenance is introduced, keep it private to construction of a local copied Position rather than exposing an in-place mutating API whose partially transitioned stale planes could be observed after a caught panic.
