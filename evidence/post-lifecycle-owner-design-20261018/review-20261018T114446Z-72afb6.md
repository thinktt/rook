# PostLifecycle22: minimum shared owner design

Preliminary choice, accepted in direction by the parent: a native generic owned capture slot replacing the existing timed locals, a single shared successful-finish report decision **used by actual offline and live finish**, an unchanged-behavior scalar Fields constructor, and one typed controlled post-event runner with an explicit clock source. Slot+scalar helper alone is insufficient if the two actual finish callers keep their own policy. No implementation is authorized or supplied here.

Source basis: exact frozen parent root-scheduler native prototype. Relevant timed/output/session/host files and released post-lifecycle contract are pinned in adjacent small-anchors JSON. Parent prototype158 and strict54/eightwire24 have passed;106 supplied driver remains unrun. None is evidence for this unimplemented design. Source/text helpers only, housekeeping0-5,8-13 with HOME TMPDIR; no Rust/build/test/engine/codegen/profiler/Git/archive/large-hash work. Parent retains final architecture/implementation decision.

## Minimum native state/API

Conceptual names, not code:

- `CaptureSlot<P>` owns `latest: Option<P>` and `eligible: Vec<P>`. These replace the **same two existing locals** captured/publications at timed.rs472-473. No additional published boolean, no Search/Node/Position/Retained or public Outcome fields. Keep all captured metadata and owned PV inside opaque P; concrete production P remains existing `timed::Capture`.
- `capture(depth, payload, publish: FnOnce(&P)->Result<(),E>) -> Result<(),E>` requires P:Clone only where needed. For depth>=3, append payload.clone to eligible history, then invoke the fallible callback; only after callback success assign latest=Some(payload). At depth1/2 invoke no callback and replace latest. No equality/deduplication, no payload-empty test, no monotone-depth assumption. New/default/read/take operations need no P:Default bound.
- Read access and `into_parts` expose/move latest and eligible into the existing Outcome result/publications fields. No extra clone at extraction; no new persistent representation.
- One `final_report(enabled, already_published, latest:Option<&P>) -> Suppressed | Retained(&P) | Fallback` owns the finish choice. Disabled or already-published suppresses first; otherwise Some chooses the retained capture, None the existing fallback arm. Empty P is still Some. This can be a free native function that Slot delegates to, so existing Outcome ABI need not carry Slot into Session. Do not reconstruct a second owned slot or duplicate the decision at each caller.

The slot tracks **eligible offline history**, not confirmed live publication. No flag in it may claim that the host actually accepted a post. Eligibility remains independent of post toggles and is collected even for NoHost, exactly as current timed Outcome does.

## Required production uses and ordering

1. At timed.rs571-593, preserve actual PV installation, BestChange adjustment, `clock.ledger.observe(work)`, elapsed and Capture construction at their current sites. Then call Slot.capture in place of the existing depth branch/publications.push/captured assignment. The callback statically calls existing publish_capture only when H::ACTIVE. Captured assignment follows callback. No clock read in Slot, no maker closure that moves capture observation, no extra observation on startup/finish.
2. `publish_capture`320-347 keeps its current control.post gate, native rendering, fine-work override, fallible host.publish and **only-then** control.published=true. Slot must not premark or replace this success flag. On error, eligible history has already appended and prior latest remains; production propagates `?`, returns no Outcome and drops the slot. Do not permit recovery into a successful finish of that failed capture. This matches current push-before-host-error and host-before-selected-assignment ordering.
3. `output::completed_events`239 must replay all eligible publications when post_enabled, then call the shared final_report with `already_published = !outcome.publications.is_empty()`. Suppressed produces no extra final post; Retained renders that capture; Fallback uses the existing zero Fields/first-root branch. Existing move selection/rendering stays outside the decision. When disabled, replay nothing and final_report suppresses. This is offline reconstruction of eligible posts, not a statement that live host posts succeeded.
4. `Session::go_live`590-619 must call the **same** final_report inside its existing successful/non-abort finish block with enabled=self.post and already_published=actual control.published. Retained and Fallback retain their current native renderer paths; existing move application and host move/game-result events remain afterward. Abort continues to skip finish post AND move; host/search/render failure continues to return an error. No new flag reset on nopost, no extra final report when posts later re-enable after a successful immediate publication. Preserve current fine-work overrides at their exact render sites.

A concrete truth table that both finish uses share:

| enabled | actual context's already_published | latest | decision |
| --- | --- | --- | --- |
|false|any|any|Suppressed|
|true|true|any|Suppressed|
|true|false|Some, even empty PV|Retained|
|true|false|None|Fallback|

Offline's boolean comes from eligible history; live's comes from successful host output. For example, depth3 capture under nopost still enters eligible history but does not set control.published. A later post command may admit a live final report. Equating the two booleans would silently lose it. Conversely, depth3 successfully posted then later nopost/post must not republish final. The controlled always-enabled/successful post22 domain legitimately uses eligible-nonempty as its seen-publication value. None is a distinct no-result state; an empty arbitrary-label PV must never become fallback.

## Scalar fields without fake chess inputs

Keep existing `capture_fields(root,&Capture,draw,selectivity)` signature, root-phase/mate-margin computation and semantics. It may delegate its final scalar construction to one native helper taking depth, depth remainder, ranking score, draw preference, u64 SearchID and unsigned elapsed word. That helper produces existing Fields: depth_token=1000*depth+remainder, actual reported_score, signed elapsed-word interpretation, unchanged SearchID. Production passes capture.elapsed_cs, which is already the native wrapped difference; controlled code passes its wrapped eventClock-startClock difference. Do not add capture/start clocks to Capture, rebuild an Adaptive instance, invent a Position/Move or cache render-ready Fields in production Capture.

The existing u32-to-i32 cast is intentional, not an overflow bug: output.rs212-221 already does it. Preserve i64-backed reported_score saturation/mate bands. Controlled supplied remainder replaces only the margin producer at this diagnostic seam, not production root phase. Keep fine-work centiseconds overrides outside this scalar helper, or finish could incorrectly freeze a prior numerator snapshot. Fallback keeps existing Fields::default and bypasses captured-score adjustment. Public SAN/display-byte logic stays outside post22: arbitrary labels are opaque payload, never fake Move descriptors.

## Native controlled runner, not a JSON lifecycle loop

Use a small native runner over typed events `{depth,remainder,ranking_score,search_id,payload:P}`, accepted start word/draw, and a static explicit observation source `FnMut()->u32`. Payload P:Clone is generic; native code knows no strings, labels, JSON or chess meaning. The cold parser validates all events and clocks first, then provides a typed event vector and a matching clock-value source. The runner owns this recurrence:

For each event in supplied order, call the source exactly once, increment its local clock-read count, form scalar captured Fields with wrapped elapsed and payload, call the shared Slot.capture, and collect that call's immediate callback reports into afterEach. Then call the shared final_report once on successful completion, with always-enabled publication and eligible-history seen state; project the retained report or suppression into onFinish. Valid nonempty input cannot choose Fallback. If an independently called typed runner is allowed empty input, return an explicit no-capture error rather than fabricate a payload.

The start word is already supplied; it is not an extra capture observation. Slot.new, shallow/deep retention, into_parts and final_report perform **zero** reads. FinishClock is eagerly validated by cold JSON but is absent from the native runner's semantic arguments/source and never read or used to stamp output. The runner's clockReads counts actual source calls, not an adapter guess or unrelated Adaptive history. Production's actual capture observation remains at the original Ledger site, not routed through this supplied-clock runner. This small typed loop is a provider/composition over the same policy owner, not a second depth/publication/finish algorithm. It adds no runtime action enum or production counter field.

Exact controlled domain: input queries1..16; query fields startClock/finishClock u32, drawPreference±10000, events1..16. Each event exactly clock u32, depth1..62, depthRemainder-64..64, rankingScore±10000, searchId u32, principalVariation0..63 labels each1..12 ASCII alnum/_/-. No letter-first rule; depths may decrease. Every query/unused finish field/label is validated before runner entry. Output sequences have afterEach, onFinish and actual clockReads; reports have depthToken/reportedScore/elapsed/searchId/entire principalVariation. Copy ownership must survive input mutation; empty/shorter/repeated PV replaces completely, repeated immediate captures remain distinct. No380-byte display limit here.

## Alternatives, risks and proof obligations

Prefer static generic FnOnce callback and this small owner first. The root slot is local, so its callback can borrow Search to publish without moving timing into recursive state. Construct Capture first at the existing site: two simultaneous closures borrowing Search for capture creation and publication would introduce unnecessary borrow/ordering problems. A resumable action enum is an optional later tool if the two broader timed controllers cannot express their PV/host/clock borrowing through static hooks. Post22 itself does not justify a general runtime root dispatcher. Pure should_publish(depth) and duplicated latest/seen/finish logic would not close ownership.

Slot.latest/eligible have the same semantic contents and clone count as current production locals: deep capture clones once into eligible history then moves into latest; shallow moves only; original PV construction clone remains unchanged. Avoid a second eligible-seen boolean or duplicate history. The controlled response may copy snapshots into afterEach separately; that is bounded cold response storage, not recursive state. Nonetheless generic outlining/aggregate moves, borrowing both fields, callback instantiations across D/H, Vec lifetime and frame/register allocation can change emitted root costs. No ABI/frame/text neutrality follows from equal field shapes; inspect a scoped default build before adoption. Do not add inline annotations speculatively.

Minimum tests for a later source prototype: all22 original cases; typed owned payload mutation/empty/shorter replacement; depths3->1 suppress final; identical deep events emit twice; finishClock/start wrap and signed high-bit; callback Drop/order trace proving publish before old latest replacement; callback error propagates with old latest intact and no successful Outcome; offline eligible/no-host versus live post-toggle/success flags; abort/disabled/no-capture fallback cases at existing native finish callers. Retain strict54/eightwire24 and exact source/artifact binding, generic/codegen/frame/clone/call review. A failure needs actual terminal evidence before changes.

This closes only supplied qualifying-capture retention/publication/finish composition. It does not decide root eligibility, ScoreDrop/BestChange admission, adjustment/capture clock ordering, root/iteration/Terminal events or activity/poll interruption. The two remaining controlled timed-route owners still need those separate reviewed boundaries. Parent decides implementation scope after this memo.
