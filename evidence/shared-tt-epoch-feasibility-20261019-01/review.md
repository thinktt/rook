**Induction and observable obligations.** Interpret slot i as valid iff group.generation==table.generation AND bit i of valid_mask is1. Initialize all group headers to generation0/mask0 with table generation1. Nonwrapping clear advances only the table byte; all previous logical slots become invalid. First store to a stale group sets its generation to current and resets mask0 BEFORE matching, treating all old payload as absent. It then follows exactly current priority semantics: search ONLY retained0..2 for identity; shallower matching store changes recent3, equal/deeper replaces retained in place and leaves recent completely unchanged. New identity fills the FIRST invalid retained slot and INVALIDATES recent, even for negative depth. Only when all3retained valid, choose least signed depth with FIRST-index ties; new>=least copies displaced payload+validity to recent then replaces that fixed slot, else updates recent alone. There is **no sorted shifting** today: moving priorities would change tie precedence. Any implementation copying/shuffling fields must move validity with the corresponding complete record. Identity0 is ordinary data, never an empty sentinel; upper mask bits must stay irrelevant/zero.

That arithmetic is a design obligation, not a measured Rust layout. Require actual size/offset/alignment and unchanged logical count if later prototyped. On stale probe the header can avoid all identities/payload. On a current group, a valid-mask test and clustered identities may replace four scattered generation/identity tests. However this is SoA WITHIN each48-byte group, not a densely separate header table: total heap bytes/group stride remain unchanged. No cache-line crossing or header working-set reduction is measured; even a20B header+identity prefix can cross boundaries, and actual load scheduling matters.

Stores must now scatter five payload fields and maintain valid bits, initialize stale headers and preserve all displaced/recent state; AoS record transfers may already lower efficiently. Wrap remains a full table write; ordinary nonwrap clear is already O(1). Allocation/zero-fill and first-touch stay owned costs. No larger entry/table capacity, arbitrary alignment, SIMD/ISA or field in Search/Node is part of this hypothesis.
