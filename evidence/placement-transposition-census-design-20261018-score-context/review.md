## Pure payload and validity

Prefer the parent's narrower payload: actual activity::Activity.{pieces[2],pressure[2],relation_queries} plus shelter::Shelter.terms[2]. These are32 bytes of scalar field payload by their declarations, not an emitted record/ABI size claim. Always recompute material/root/personality weighting through shared existing native owners if a later cache is selected. Weighted activity and shelter, tempo, positional subtotal, retained P/G, full score and Finished are outside this payload. Current activity::weighted (activity.rs:484) and shelter::combine (shelter.rs:302) are private; a later cache would need narrow shared native pure composition owners, never a copied formula in adapter/cache. The census needs no extraction: full_impl already has both complete actual records at evaluator.rs:373–380 and can observe these produced fields after existing computations.

Placement suffices under coherent production Position/influence:

- Influence::new (influence.rs:36–89) gathers all listed sources with board-owned ray behavior; add at154 uses wrapping u8 addition. Integer modular sum is associative/commutative even when normalization carries/discards. It is not a chronological saturating accumulation.
- Activity::compute (activity.rs:94–156) independently sums each piece's i64 contribution, then rounds each side once; each piece's rounding/selection remains internal and fixed. Marks are bitwise OR at242, hence source-list order independent. Categories/pressure destinations use board/influence and fixed geometric order; no floating arithmetic or running global saturation exists here. Shelter components scan board/current king/influence; compose at286 uses integer phase arithmetic and per-side rounding before terms are combined. Existing per-piece operations must stay in their native order; associativity of source sums is conditional on admitted bounded integer safety, not permission to reassociate arbitrary i32 formulas. This design introduces no arithmetic reassociation.
- Position::phase at356 depends on counts and starting_units. Coherent counts are placement-derived; starting_units is the sum of per-square starting_credit (410/527), updated by replacement at238 and rebuilt at422. Root phase is fixed by RootContext::new, but current phase can change along search and returns to the same value at the same coherent placement. Equal boards do not alone certify an arbitrary publicly mutated inconsistent Position.
- Activity raw pieces/pressure/query count and shelter terms do not consume moving side, rights, EP, halfmove/history, pawn cache origin, retained age/P/G, root average-depth/personality/draw, or root side. Tempo and finish DO consume some of these, which is why they stay live. Shelter terms depend on the produced activity pressure and current phase, not the pawn-cache-selected entry.

The root-bound weighted alternative is valid only while all relevant context stays fixed. RootContext fields are public (evaluation.rs:79), Evaluator.root/parameters are public (evaluator.rs:262); arbitrary API callers can mutate root material values/counts/average_depth independently. weights are private and rebound only by new/begin_search (272/285), so editing public parameters mid-search alone does not instantly change bound weights, while editing root can change material immediately. Actual Session.prepare_go binds parameters at450 before search entry; production full/ordinary/Q receive this evaluator and do not mutate root fields in the examined owners. This is a production lifetime invariant, not an unrestricted API guarantee. Pure payload avoids making a mutable-root/personality validity premise. Reset census at each actual begin_search, including root attempts within that same epoch, but do not reset per iteration/ordinary↔Q; never carry state across searches/parameter binds.

## Exact witness and identity

Use explicit placement equality, not hash-only or final-score identity. AttackBits (attacks.rs:8) derives Eq over fouru64 planes; from_board at78 writes each low-four tag bit at each square. Piece::new (types.rs:96) produces legal codes1..6/9..14, EMPTY0; all fit four bits. Thus coherent planes encode every legal tag/square injectively, including empty and color, so AttackBits equality is a collision-free32-byte placement witness. This says nothing about emitted cache/argument layout. Piece(pub u8) and Position public fields permit malformed high-bit tags/independent board mutation: plane equality is not full-byte-board equality over those arbitrary states. Position replacement updates attack planes (240), parser/rebuild initializes them (423), and validate checks matches_board (455). Do not infer coherence merely from a fingerprint.

For the first census prefer board64 as independent raw witness and exact slot comparison; independently derive four planes from every raw board offline and verify agreement with the existing attack_view at the diagnostic hook. This avoids selecting a new private-plane serialization/hash API before evidence. Report both theoretical key payloads (64 vs32), not a proved cache size or cheaper native ABI. An alternative approved census could serialize actual planes directly, with board64 coherence checks retained. Both candidates must reject/flag any board/tag/count/starting/plane inconsistency, rather than silently admit false reuse. Ignore side/rights/EP/history for placement matching; optionally record them only as provenance showing matches across metadata changes. A slot's index is a predeclared stable board-only digest; digest collisions are misses after exact witness comparison. Existing complete-position fingerprints can include nonplacement metadata and must not silently become a stricter key that conceals intended recurrence.

## Proposed diagnostic experiment

One isolated derivative, D=true plus an explicit census build feature; no runtime bypass/cache in production. Use a feature-gated external diagnostic sink, not a new Position/Node/Search/Evaluation/Retained field. A call immediately after actual activity+shelter computation records a FULL encounter; do not instrument only age0 nodes or only standalone full callers. Count both FRESH and normal full but label them separately; production54 primarily uses normal full. Optional call-site source categories must be diagnostics-only and cannot change evaluation selection/charges. New/begin_search lifecycle hooks establish an epoch once per actual search. The driver must verify one actual evaluator/epoch owner per sequential54 workload; if ownership becomes concurrent/multiple, use an explicit diagnostic scope rather than an address key surviving evaluator moves. No implicit cache reset on root retry, iteration, pawn replacement, ordinary/Q handoff or retained refresh.

The existing full_impl must ALWAYS compute material, select/fresh pawn entry, pawn_terms, activity, shelter, structure/progress/central/patterns/tempo, retained updates and single finish in its present order. No experimental lookup result feeds any evaluator result. PawnCache hit/replacement/order and every charged pawn/activity relation query remain actual. Even a later production hit would have to replay the exact saved activity.relation_queries into the same native query charge sum at evaluator.rs:439; it cannot subtract semantic work because CPU calculation was avoided. Influence remains required for pawn/progress/central/other work. Census records queries represented by hypothetical hits as semantic work to retain, not work saved. No search stopping/work/Host/poll/randomness path changes.

Predeclare direct-mapped capacities64,256,1024,4096, each independent empty table per epoch and one stable placement digest policy. At every actual encounter: count probe; index; if occupied and exact board matches, count verified potential hit and require ALL pure payload fields equal to the actual fresh producer; otherwise count empty miss or occupied-key replacement; store actual current witness/payload after the decision. Refresh every encounter, including hits. Maintain separate denominators/hits for normal vsFRESH and age0 vsage>0 to expose the new opportunity rather than recycle old metric. Per capacity record probes/hits/replacements, hit activity R sum, and mismatch count; optional repeat-distance histogram uses last actual ordinal in the same slot. Occupied replacement is not proof of a capacity-caused lost hit; without an unbounded set, no unique-placement count, ideal-cache hit rate or compulsory/capacity separation is claimed. No tuning hash/capacity after observing favorable outcomes.

For independently auditable accounting, record an ordered binary stream per native process to a dedicated file/FD (never protocol stdout/stderr): epoch header, then each actual full encounter's exact board64, actual pure payload and minimal flags (FRESH/age class; ordinal implicit). ## Preliminary decision

The pure payload is the better validity boundary than weighted root-bound entries. It can capture genuine placement transpositions across chronological lists, side/rights metadata, retries and iterations without caching retained or pawn-derived state. Exact plane witness can later reduce identity payload under a proven coherent-domain invariant; initial independent board logging makes that proof inspectable. None of this establishes meaningful recurrence, avoided CPU share, useful capacity or net benefit. First obtain complete54 exact-hit/charge-volume counts at bounded capacities; only if material opportunities remain should parent consult architecture advice and consider a narrow native pure weighting extraction/cache prototype. No cache/prototype/counter execution is authorized by this memo.
