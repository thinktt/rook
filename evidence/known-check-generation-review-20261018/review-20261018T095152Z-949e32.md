## Lifetime and equivalence proof

At ordinary entry the local `Position` copy is immutable. Repetition admission, learning, remembered results, evaluation/cache updates and a completed null trial do not mutate that copy. Thus its `checked` remains valid at generation. Early returns before line615 simply never use the admission. Root ordering, retained work and retries likewise do not mutate the root `Position` passed to generation.

Do not inherit a parent's noncheck fact into a produced/null child. Null flips the moving side and removes EP; a parent's safe king does not prove the new moving king safe, especially under broad setup ingress. Existing null `Request.checked=None` stays exact. IIO creates a different child and also supplies None; its own entry classifies that child. IIO reorders an existing parent candidate list, not the parent placement. Scout/research retries revisit the same child with changed bounds; their original request handling remains intact. Frontier `Some(checking)` applies to the produced child, mainly entering Q, and must not be confused with parent knowledge. Predecessor.checked is expressly the predecessor's fact. History push/pop, retained/cache updates, session move/undo/remove/setboard and separate root acquisitions cannot become a check cache.

`in_check` uses placement-owned persistent `AttackBits` (`movegen.rs:136–138`); ordered discovery uses mailbox `find_attackers::<2>` (82–127). Both describe geometric attacks, including pinned attackers and adjacent kings, not legal attacker moves. Their equivalence and the existing placement/bit-view invariant are proof obligations, rather than a new representation. For a valid known-false fact the ordered finder would return `len=0` and zero squares exactly. For known true, a Boolean cannot replace first-two identities or their order.

`GenerationSafety::new` (247 onward) must still execute: noncheck triggers its absolute-pin ray scan when enemy sliders exist. Noncheck never implies unpinned. Preserve EP prefix, long/short castling admission and transit safety, pawn order, special single-check prefix behavior, piece chronology/directions and final own-king safety. Do not add a double-check shortcut; joined EP can remove one checker while blocking another. Empty checker substitution only in a proven-false path makes all existing branches see the same inputs. Full natural order is observable after ranking and in first-iteration/root behavior.

Discovery itself has no semantic charge, host poll, RNG or learned/cache write. Exact lists preserve charged search/relation work, cache accesses and controlled work-poll interruption boundaries. No change is proposed to early returns or charge sites. Host wall arrival may naturally differ if a later measured trial is faster; this audit establishes no wall-time outcome.

## Private API choice and next falsification

Prefer an initial ordinary-only private admission into a shared body: an existing `checked` bool can mean false → empty Checkers, true → original discovery; alternatively Option<bool> makes unknown explicit, with None/Some(true) both discovering. Public `generate_legal` and capped helper keep their unknown behavior/signatures. Do not require or compute an additional Boolean, store any fact on Node/Position, or persist it between calls. A private no-check promise must be documented against the exact immutable position/side; lying about it can admit illegal moves. Extra argument/branch/call overhead remains uncertain, and ThinLTO can still clone a common body.

A const specialization could erase discovery and checked-only branches, but adds a second full-generator monomorph with possible text/layout/I-cache costs. The current body is substantial. Prefer the runtime route for the first bounded codegen investigation; choose specialization only after emitted-scope evidence. This is not a prediction that runtime code is smaller/faster.

Cheap later falsification: compare exact ordered full lists for known-false versus unchanged unknown entry over existing 10k/projection coverage plus fixed pins, castles, EP (including joined cases), promotions and broad ingress. Select false test boards independently via mailbox attack truth, and retain checked single/double/3+ witnesses on unknown paths. Exercise null/opposite-king check, IIO and scout/retry/history restoration without propagating facts. Keep every existing ordering test, then native suite, strict original54 and eight-wire/24 searches before any timing. Inspect full/default/capped emitted scope only after clearance. A diagnostic census, if selected, should count reached full-generation sites by existing checked value, separating ordinary/root/Q and exits before generation; do not infer calls from LLVM block counters. Expected saving is only redundant checker discovery on reached known-false calls: pin scans, projections and all candidate work remain. No measured upper bound or gain is available from this source audit.
