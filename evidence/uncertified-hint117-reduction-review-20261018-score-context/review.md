## New exclusion theorem

Write L/U for the incoming ordinary window, A/C for the saved effective evaluator bounds. Consider a node which reaches the main candidate loop and completes normally. The bounds gate has already established A<U and C>L (`src/ordinary.rs:800`; `ordinary_policy.rs:53` onward). The loop starts best=A and running lower=L (`ordinary.rs:936`). Its only assignments to preferred are a generated checking-mate move before the loop or an actual main candidate inside strict best improvement and strict running-lower improvement (`ordinary.rs:879`, `ordinary.rs:1050`). The frontier-estimate shortcut still consumes a move from the actual generated list; skipping its child search does not turn it into an uncertified descriptor.

**If A<=L, an inherited empty-source hint cannot remain the preference at a completion learned update.** Such an update requires min(best,C)>L (`ordinary.rs:1075`). Since best starts at or below L and only increases, a first candidate must raise best strictly above L. Until that crossing, running lower is still L. That candidate therefore also raises running lower and replaces preferred with its generated move. Every later replacement also comes from that same node's legal list. A successful quiet-mate replacement is likewise a generated move. No later path restores the inherited hint. The preferred source is consequently occupied in this unchanged parent placement when the learned update is attempted. This is a source/control-flow proof, independent of score correctness or whether the child was searched.

For an initially uncertified hint that remains unreplaced, **A>L is necessary**. In that case running lower starts below A. Any candidate score>A would both improve best and exceed running lower, replacing preferred. Thus the inherited hint survives precisely when every consumed main-candidate score is <=A, provided no earlier quiet-mate replacement occurred. On that path best remains A, and min(A,C)>L follows from A>L and the already passed C>L gate. It is unnecessary to add a separate final-clipping assumption.

These statements match the released strict-improvement/completion rules (`spec/ordinary-iterations.md:378–442`), rather than proposing a change to those rules.

## Why depth and query metadata do not close the gap

The production remembered owner permits a no-score result containing a nonnull hint even when the final matching retained record has sufficient depth. `remembered.rs:108–140` exports metadata before testing cutoff permission; an exact score strictly inside (L,U) is not a usable cutoff. A null record does not clear a previously exported nonnull hint. Query considers recent before retained (`remembered.rs:230–246`).

A conditional owner trace is therefore: a retained record of the queried identity has sufficient depth, an interior exact score and null endpoints; a shallower same-identity record supplies nonnull endpoints from recent. Storage explicitly routes a shallower matching-identity record to recent (`remembered.rs:197–208`). Query keeps that recent hint while exporting the retained record's depth/bound metadata and returning no score. Retained Exact also does not request the Lower-bound tail phase. This refutes the proposed metadata/depth exclusion, **not** production reachability: it does not provide the placements, chronological search stores or candidate scores required by a public composition witness. Supplying these records directly to a component is not such a witness.

## Provenance boundary and precise remaining obligation

There is a useful conditional provenance induction. Starting with a cleared table, newly discovered preferences come from moves generated in the store node's placement. If every matching table lookup preserves that placement (or at least preserves the hinted source's occupancy), then inheriting/re-storing hints preserves occupied sources. Erasing move-kind bits does not erase the source endpoint. An empty source therefore requires a break in this provenance condition somewhere since clear; it is not explained merely by promotion/castle/en-passant kind erasure.

Actual matching does not establish the condition. `remembered.rs:93–95` checks generation and secondary identity after selection of a primary-derived conflict group (`182–190`); it neither compares placement nor certifies occupancy. Even an initially sound hint can be propagated by fast/shallow stores after a cross-placement match (`ordinary.rs:771–842`). No global hash-collision argument, reachable pair or chronological composed witness was proved here. Clearing between searches does not itself exclude a within-search provenance break.

The actionable unresolved production branch is now narrower: a normal second-half main completion with no usable remembered score, an inherited nonnull hint whose source and destination are empty in the current placement, A>L, and no consumed main candidate score>A. The actual gates/chronology must also permit reaching main rather than an earlier return. Alternatively, a first-half branch needs L<-10000 as well. Proving that these branches are unreachable requires an actual caller-window/evaluator/candidate theorem or a provenance guarantee stronger than the current hash match. A concrete admitted public witness requires the originating stores and one real root search chronology, not independently supplied table records or evaluator endpoints.

The empty-source guard still returns before both killer and history updates (`ordinary_policy.rs:406–422`). Released cutoff-memory direct events inherit occupied-source candidate bounds (`spec/cutoff-memory.md:75–79`; `spec/search-candidate-order.md:31–34`), while ordinary completion consumes its remembered preference. This review neither assigns missing specification behavior nor justifies suppressing those updates. No full production-discharge claim and no reachable counterexample claim is made.
