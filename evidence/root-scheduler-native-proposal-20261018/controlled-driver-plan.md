# Controlled driver follow-on boundary

After independent review of the native iteration owner, expose three routes through one small native supplied-reply driver, rather than a JSON-side pass loop. A Reply carries adjusted root-relative score and search work; an initial-slot-indexed pair carries first and possibly-unused retry. The driver alone advances absolute N for actual attempted replies, calls Iteration.next/returned, records typed pass metadata and snapshots the produced ranked prefix. It does not fabricate legal chess children or charge relation work. Its output retains Completed, per-pass Attempt/returned/N and the prefix; the cold frontend only validates complete exact input schemas and projects initial slot IDs to labels. The driver remains outside recursive Search state and is not used as a production child provider.

The rootWorkSchedule route calls the same native policy/order_tail routines used by the actual index1 boundary. The next-iteration projection applies those same routines to the produced ranking without creating/entering another iteration. Native row IDs cover production512 roots and must not be narrowed to the diagnostics64/32 candidate limits. Unique labels and conservative exact-interchange sums (including all unused retries) are validated eagerly before native execution; production arithmetic receives no2^53 domain policy.
