# Remaining controlled timed owners: bounded design review

Preliminary recommendation: a statically dispatched native root-sequence driver over the existing scheduler, with explicit child/clock/payload effects, plus one separately shared charged-unit/poll-admission primitive. Both controlled routes must call this driver; actual timed search must also use its event-order/completion owner. Adaptive arithmetic plus CaptureSlot alone is insufficient: leaving cold code to admit score-drop, best-change, easy, terminal or interrupt transitions would create the second root algorithm the parent wants to avoid. A resumable native event owner is a viable fallback if real Search/Clock borrowing makes the static boundary impractical. Parent retains the architecture choice; no implementation is supplied.

Basis is exact108 scheduler/engine/timing/work ledger and the separate frozen source-only post109 prototype, not mutable root. Small source/spec anchors are adjacent. post109 is unparsed/unrun; its state/finish design is not a validation claim. This task performed only source/spec reads, small anchor hashes and memo/receipt writing. No native jobs, Rust parsing, source edits, builds/tests, codegen, engine/profiler, archives or large hashes.

Supplied_iteration at327 cannot merely be called then timed afterward: a root or poll stop must prevent later attempts and ranking from occurring.

- `timed.rs:563`: restricted-first ScoreDrop consumes the fixed previous-iteration best and raw returned score, even when no increase occurs. ## Minimum shared state and transition boundary

Keep existing root rows/current Iteration and its pending Attempt; current depth, fixed previous-best and actual search-wide counts/source; retained Adaptive state in the native timing owner; owned latest/eligible capture slot; and one typed termination descriptor distinguishing normal/root/iteration/poll/provider failure. Original-slot identity is enough for labels; payload P is an actual owned snapshot supplied after native PV installation. Do not add Node/Search fields, vtables, a maintained second work counter, a published flag or a new copy of ranking state. Production may loan the same existing Clock/scalars through effects; controlled sources can own scalar Adaptive/clock state without pretending to have a chess root.

The shared native owner must sequence these operations, rather than requesting an externally supplied list of adjustment events:

1. Begin depth and freeze scheduler policy from absolute N; get next original-slot attempt. Prepare the actual candidate's child once. Execute first/retry requests using scheduler output; retain both passes' work. If interrupted, stop before returned/ranking, preserve prior capture and completed prefix, and do not synthesize a score.
2. For a scheduler Completed: restricted-first ScoreDrop; if best_changed, install the native PV/payload basis, BestChange adjustment, metadata clock observation, construct owned capture and call slot.capture; then root-completion check. The callback interface must distinguish pre-adjustment PV installation from post-observation Capture creation, or extraction would move a production observation/clone site.
3. Only when all roots complete without stop: easy selection from frozen policy plus current N, iteration check, shared actual terminal decision, then carry ranked rows and set previous_best on continuation. Never update previous_best mid-iteration.
4. Exit with explicit partial/completed/iteration-exhausted ownership; public rendering, host finish/abort/fallback and JSON projection stay outside. The existing actual stop/work/PV owners must remain available without enlarging public Outcome/Step.

Use typed source reads distinguishing initialization, adaptive adjustment/root/iteration/poll and metadata capture. Actual clockReads/clockChecks must be generated by the observation closure when Adaptive actually requests a reading, not inferred from stage names or counted a second time. A static observer can project only admitted controller reads, leaving production defaults empty by specialization. Capture metadata still reads at its original site and can update ledger.last/fine numerator while being absent from the adaptive trace. No observation is justified solely to format a response.

Production currently ignores the Boolean returned by its iteration Clock.check and lets Terminal.reason decide completion using signed elapsed. Do not replace that with an immediate unsigned Adaptive stop merely because the bounded controlled domain gives the same answer. Preserve both the observation/easy effect and authoritative ordered terminal decision. Root and poll checks keep their existing Boolean stop ownership.

A terminal seam is needed as well: controlled scores ±2000 and depths1..8 activate only elapsed and the sole-candidate losing-alternative rule with nonzero average. Share Terminal's ordered early decision prefix (including elapsed/score/alternative gates), with full production reason continuing through ceiling/md/mate rows. Do not invent a Position/root phase/personality for labels or force md=number-of-supplied-depths. An explicit controlled-domain completion policy may end list exhaustion with stopped:false; production's missing natural stop remains IterationCapacity error. This boundary must be reviewed as a native extraction, not an adapter formula for the sole-candidate case.

## Two clock/activity providers, one root event owner

For timedRootSequence, a native supplied provider adds the executed reply's work to absolute N and advances its current supplied elapsed at completion, before the score reaches the scheduler. Retry time/work count only if actually requested. Observation returns start+elapsed modulo2^32 without advancing it. No polls are inserted. Each native pass records original candidate ID, actual exploration index/attempt/window and post-reply cumulative work/time. Identity-to-string mapping remains cold.

For workTimedRootSequence, a native supplied activity provider owns relation-first then unit-by-unit execution of each selected reply. Add its R before any search units, then charge each N unit through the same extracted increment/poll-admission primitive used by engine.charge_node. The primitive preserves limit-before-increment and credit-before-positive4096-poll semantics; its result can request the existing actual work_poll phase without moving host policy. Relation charges do not poll. Do not group real production evaluation this way: only controlled supplied activity uses the explicit R-first contract. Production R continues to originate at existing evaluation relation sites, sampled by work().

That controlled provider must use actual Ledger and Adaptive maximum-poll behavior; no clock formula in cold JSON. At a stopping poll it returns Interrupted even on the final supplied unit, with credited N/R and no score. Remaining units/retry/scheduler.returned/adjustments/capture/root/iteration checks do not run. No reset occurs at candidate, retry or iteration boundaries. Relations-only work can cross maximum without a poll; at depth1 root/iteration reads are suppressed, so such a crossing does not invent an early stop. Zero-unit replies complete normally and can still cause metadata/adaptive observations. Average0 does not disable nonzero maximum. Final totals and final observed clock remain separate from selected capture metadata.

The increment primitive alone is not sufficient closure: cold JSON must not loop units, schedule polls or resolve interruptions. Native supplied activity owns that loop and calls the shared primitive/clock owner; the native root driver owns all resulting completion/event decisions. Ordinary real recursion remains the source of real activity and unwind/history restoration, not a supplied-activity simulation.

## Alternatives and preliminary choice

**A. Static generic driver/effects (preferred first).** Extract the existing actual root orchestration around RootIteration into one native driver parameterized by an attempt provider and small static timing/PV/capture/observation effects. Production provider retains actual child/history/request/window/randomization and returns normal versus interrupted typed outcomes; controlled providers retain supplied reply/clock/activity cursors by original slot. Both use the same completion transaction, scheduler, Adaptive, terminal prefix and CaptureSlot. Scope each clock loan to an operation; do not hold &mut self.timing while calling back into Search. An actual child handle must survive a retry without rebuilding or discarding its mutated retained/evaluator state. Keep Noop/default instrumentation explicit by compile-time mode. This removes the duplicate recurrence and avoids runtime action dispatch, but can increase root monomorphs, code size, stack captures/outgoing arguments and borrow complexity. It is larger than a few scalar helpers; backend cost neutrality is not implied.

**B. Resumable typed native controller.** Own the same scheduler, pending completion and phase in a stack-local controller which emits ordered actions: Attempt, ScoreDrop, PrepareBestPV, BestChange, Capture, RootCheck, IterationCheck/Terminal, Done. Callers execute effects and acknowledge typed results; interruption is an explicit terminal transition. Both actual timed loop and a native controlled runner interpret the same controller, while JSON only validates/projects. This avoids holding Search and Clock borrows across callbacks and makes stopped-prefix ownership explicit. It adds runtime phase dispatch, an aggregate pending completion/action, possible wider state/frame and more invalid acknowledgement states to rule out; an action interpreter must not duplicate admission guards. It must preserve exact read/clone/poll sites rather than moving all effects into a batch at the end. Use this only if A's scoped loans cannot express actual ordering cleanly, not as an unsolicited general engine framework.

Either alternative must actually replace the relevant production admission loop. A cold-only timed driver calling RootIteration+Adaptive+Slot while production retains its current recurrence is not a shared timed owner. A planner returning booleans like should_drop/should_capture with each caller arranging effects independently is too weak for the required coupled ordering.

## Admission/projection traps and phased gate

Exact full eager schemas: timed query count1..16; workTimed1..4; both unique labels1..8, each1..24 ASCII alnum/_/- (no letter-first rule), depths1..8, each depth row in immutable INITIAL label order, exactly two replies/label. Every unused retry and stopped suffix remains validated. average/maximum0..1000000 with maximum>=average; start u32 and fixed Boolean inCheck. Reply score±2000, work0..50000; timed elapsed0..1000000, workTimed relations0..50000. Do not import unrelated narrow diagnostics' selected-PV/history/move validation. These bounded sums fit native counts; do not impose controlled size/numeric bounds on production.

Scheduler retry equality at the original upper bound, stable equal scores/work, pinned-first sort timing and original-slot lookup remain observable. ScoreDrop uses the returned score before the ranking deduction (after actual production root random adjustment), capture uses ranking score, and fixed previous best remains from the preceding iteration. Easy is admitted on unrestricted-start AND final threshold, even at depth1 where its multiplication can occur without a clock read. Two adjustments can cause consecutive equal-time reads. BestChange at depth<=3 increments history with no read. Adaptive history rotates once on a greater observed depth, including a poll, not once per missing depth or provider work block.

Projection domains differ: timed.depth is last executed depth, workTimed.depth is selected capture depth or0. A work interrupted pass has completed:false/score:null, whereas a normally returned retry's initial pass retains its supplied score even before candidate completion. workTimed absent selection/score are null with selected metadata zero; public fallback is outside this operation. Stage index is current exploration index including retry; iteration completion index is candidate count and initialization index/depth are0. clockChecks are adaptive-control reads, not all capture/source reads. workTimed.lastElapsed is last OBSERVED time, not a fresh calculation from final totals; metadata observations can change it even when absent from the trace. Integer/signed elapsed and binary64 behavior must remain with native Ledger/Adaptive/Terminal.

Proposed phases, parent choice: first extract/bind actual completion/clock/terminal owner with source-level default-path preservation and meaningful coupled-order tests; then add typed supplied-elapsed provider/native runner and exact timed transport; then extract shared charge/poll admission and add native activity provider/workTimed transport. Validate each actual composition with native tests, full relevant originals, complete existing DIAG union, strict54/eightwire24, independent raw/source/artifact/actual-exit reconciliation and scoped default root/charge-path codegen. Tests should cover ScoreDrop-before-BestChange, easy crossing versus restricted-start, skipped adaptive reads, retry equality, final-unit poll, relation-only/zero-unit work, interruption before any capture versus prior capture, partial retry and clock/identity invariances. No implementation, execution or measurement is authorized or performed by this memo. Keep post109 separate until selected and validated.
