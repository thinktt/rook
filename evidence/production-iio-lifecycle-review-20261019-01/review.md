## Non-obvious invariants checked

Caching Extensions once per pass is sound for the current helper: it stores source material/pawn facts plus candidate len and count of recaptures to the previous destination, not order-sensitive rank. Stable front promotions preserve that inventory throughout the pass. For a tail the contract's suffix-only phase is the input list; a sole remaining evasion can therefore receive fresh2 even when the original main list had two moves. Main Extensions is built from the complete list after initial IIO and remains valid across tail reordering because its full inventory does not change. This depends on the present helper continuing to be order-insensitive; a future rank-dependent extension would invalidate the cache proof.

The promotion invariant is inductive: before visiting index i, positions start..i are alreadyvisited. Moving i to start shifts only that visited prefix; original unvisited i+1..count stays at those indices. Moving the aligned flag row with the move retains prior-pass OR even for a promoted candidate. Every target starts from the preceding pass's actual resulting sequence; early cutoff does not roll back shared stores, flags or ordering, nor skip the next target.

IIO cannot replace the parent's best or PV directly: it receives no parent best/lower references and never calls replace_pv at plyP. Recursive children only reset/update P+1 and deeper PV rows. A tail may overwrite the scratch child row after the first main return, but the parent PV was copied into its own row already. The next searched child resets its PV on ordinary742 or Q245 before success. A frontier skip cannot accidentally copy an IIO child PV: its estimate<=max(best,lower), so it cannot simultaneously create the strict best-and-lower improvement required at1069–1074. This local argument is stronger than merely observing an empty parent PV in a fixture.

All Result-returning branch edges inspected pop history before applying ?: null853–854, mate-probe931–932, main1066–1067 including failed scout/retry, and IIO1175–1176. Thus Stop/NodeLimit/HostIo at a descendant unwinds one pushed boundary at each ancestor. A retry shares the same existing boundary and child state, as it should; no second push/age increment occurs. The parent full state may have refreshed before the branch and remains that refreshed state; restoration means not replacing it with child retained values, not reverting the parent's own evaluation. Panic/unwind across arbitrary custom Host panics is not guaranteed by this Result argument and is not established here.
