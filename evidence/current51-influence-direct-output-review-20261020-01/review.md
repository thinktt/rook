**Conditional GO for a narrow source/compiler discriminator; no implementation selected here.** Safe Rust can fill final scratch storage with rollback semantics. It cannot leave an `Option<Influence>` physically `None` while safely borrowing its payload: initializing an enum payload requires a valid `Some`. The acceptable route is an exclusively borrowed temporary `Some` plus a small unwind guard restoring `None` until successful commit. If physical `None` throughout construction is mandatory, this route is NO-GO without a separate128-byte object or uninitialized/unsafe storage.

The actual source boundary is small. `Influence` contains only `profiles:[[u8;64];2]` (influence.rs33–36), so zero is a fully valid value with no destructor. A minimal outline has one common coherent numerical fill body operating on an already-zero, initialized `&mut Influence`. The existing private by-value wrapper may construct zero, invoke that body and return it for old callers/tests. On the trusted None branch only, a stack-local rollback guard exclusively borrows the actual Option, installs one valid zero `Some` directly in its final slot, and passes only its payload to the fill body. The body keeps current mathematical loops/stores, but has no local `Influence` and returns unit. The zero-precondition is private, documented and proved by each of its two initialization sites. Do not also zero the whole output inside the body: scalar colors need one initialization, while duplicate caller/callee zeroing would add work and rely on optimizer elimination. An alternative full-overwrite API which zeroes internally is safe but must price the mandatory valid Option initialization separately; safe Option APIs do not expose uninitialized payload bytes.

The guard remains armed through the completed fill and the existing test-counter increment, then commits and releases its borrow. Only after commit does the unchanged DIAGNOSTICS stat increment run, and the function returns `scratch.as_ref().unwrap()`. On unwinding during fill or precommit test-counter update, Drop restores None; old code also left None. On a later stat panic, both retain the completed Some. Panic-abort provides no postfailure observation; an unwind-safe library/test route still needs rollback, rather than relying on abort or assumed coherent nonpanicking input. The builder accepts no callbacks and the guard holds exclusive scratch access, so no safe caller can observe intermediate Some/partial bytes. No catch_unwind, unsafe pointers, MaybeUninit, Node fields, persistent flag, allocation or public API change is needed. Public false/scalar behavior and suppliedSome authority remain unchanged. A bare get_or_insert/insert followed by fill without rollback is rejected: caught panic would expose a partial Some where old code left None.
