**Yes: exact placement plus an unchanged bound root/personality context is sufficient to reuse already-weighted activity and shelter. The old hit reweighting was a deliberate broader root-independent payload design, not an unavoidable requirement for equal placements inside one fixed native root. ## Boundary that must be narrower than existing public Search

Search.evaluator is PUBLIC (engine35); Evaluator.root and parameters are PUBLIC (evaluator262–265), and RootContext's material inputs are public (evaluation79–85). A client can prepare a root, replace/mutate root values/counts/side/average_depth, then call a public selected/continued subtree on the same Search. Merely moving a cache from Evaluator into Search cannot detect that. Public prepare_root returns before later continue_subtree; its borrow alone does not seal that interval. A persistent epoch counter incremented only by begin_search is insufficient against direct public field mutation. Changing Parameters alone takes effect on the next bind; direct root mutation can affect material immediately.

A defensible distinct mechanism is cache permission limited to one privately controlled blocking native root-run epoch, revoked on EVERY return/error/abort, with begin_search/rebind clearing before admission and no public method able to import an attested token/map. Standalone public subtree calls must bypass or establish their OWN fresh scoped epoch; they cannot silently inherit a prior prepare_root token. This is an ownership requirement to design, not an existing proof. It avoids per-hit context-signature comparisons, but safe borrowing/cleanup/default ABI must be concretely demonstrated before any implementation trial. Without such a seal, reject weighted reuse.

All public Evaluator full/fresh/observed methods and selectors with possibly prefilled custom scratch must still neither consume nor populate the cache. Equal board does not imply equal caller-supplied Influence; old bypass tests939 onward remain relevant. Native root scratchNone→ensure, ordinary763/795 scratchNone→ensure, and Q's own scratch/selector paths need the same provenance audit, including observed Search calls. Existing observer callbacks only receive components/details/stages, not permission to treat arbitrary supplied maps as native.

The narrower production-go seal has concrete support. A future concrete spelling could activate only after root binding and revoke at run_work_timed_entry's existing common return/error cleanup (plus panic-safe policy if required), clear storage once for the new bound root, and admit only private trusted full/selector routes during that borrow. ## Distinctness and recommendation

The reviewed frozen experiment24 source/decision contains only the raw root-independent payload and reweight-on-hit path; its explicit rebind test demonstrates that design. No weighted/private-active-epoch attempt appears in the bounded trial/source/backend records read. A new sealed-domain payload would be a different mechanism, not a resize or ordinary-variability rerun, but that distinction does not reopen parked24 automatically. Do not compose it with26–32 or infer an improvement from the old near-miss.

Recommendation: this is a distinct, source-feasible active-go payload mechanism, with a real epoch boundary matching the old populated census scopes. Keep it separate from parked24; reject immediate reuse under public Search ownership alone, and require one concrete sealed-epoch/default-call design before considering a new source prototype. It must preserve public mutation/custom-map bypass, same-epoch side/rule/chronology cases, root-change invalidation, actual R/retained/observer equality and all stop/error cleanup. Even then, Search's box metadata and allocation/clear remain; changed borrow/argument/monomorph boundaries can retain or worsen full/root frames. Old backend growth is not proven to disappear merely by removing the790B helper. No dynamic hit-helper instruction cost or hypothetical CPU gain is claimed.
